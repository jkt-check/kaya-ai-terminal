## 欢迎使用 kaya

kaya 是一款 macOS / Windows 桌面应用,定位是**为 AI 开发者打造的 AI 终端**:完整保留真实终端的工作方式,把模型管理、编程 Agent 管理、安全网关和 AI 大脑放进同一个开发工作区。打开应用,你会看到左侧是 AI 大脑的对话窗口,右侧是一块和你熟悉的终端一样的面板(macOS 上是 zsh,Windows 上是 PowerShell)。AI 可以读取经脱敏的终端输出,帮你解释命令、查询环境和跟进 Agent 进展;AI 工具执行使用独立子进程,不会直接在你的普通 shell 提示符中输入命令。

每个终端 tab 都是一条独立的 shell 会话:你可以在不同 tab 里同时跑 Claude Code、Kimi Code、OpenCode、Codex 等多个编程 agent,它们**真正并行**;在聊天框里敲 `@` 就能唤出正在运行的 agent 列表,@ 谁谁就成为当前对话的协同对象——你交代任务、它干活,确认与决策始终由你把关。跨 agent 协同也随之成立:把一个 agent 的结论带到对话里,再 @ 另一个 agent 继续推进,你在聊天框里统一指挥。需要接力时还可以把后续任务写进**跨 Agent ToDoList**:目标 agent 空下来时会先问你要不要执行,你点头后才派发,干完由 kaya 验收闭环。

kaya 的目标是让你在**不离开真实 shell**的前提下获得 AI 协助与多 agent 协同:你能继续使用自己的 shell 别名、自己的脚本、自己熟悉的快捷键,AI 不会把你困在一个沙箱里。

> 注意:AI 不会接管你的整个终端。AI 默认只读你的终端输出;只有当你**打开顶栏的 coding 模式开关**、且在对话中的授权卡片里明确允许、并且该 tab 运行的是受支持的 AI CLI(Claude Code / Kimi Code / OpenCode / Codex)时,AI 才能代为向该 tab 输入。coding 模式开关是「驾驶」的总闸门:开关关闭时,对话端连向终端 AI 发输入的能力都不存在(该工具不注册);打开之后仍需要每个 tab 单独的授权卡确认。授权绑定当前进程,进程退出或 tab 关闭即失效;随时可点 tab 上的 🤖 角标撤销。你的普通 shell 提示符永远不接受 AI 输入。同理,AI 帮你修改编程 agent 的配置文件(如 Claude Code 的 settings.json)时,每一次修改也都必须经你在授权卡片上明确允许才会落盘,授权只对当前会话有效。

## 产品能做什么

kaya 重点呈现**四项核心能力**,并以**完整终端**作为基础。

| 核心能力 | 对应的现有产品能力 |
|---|---|
| **模型管理与多供应商** | 模型库与供应商配置、模型发现与元数据、自备 API Key、供应商 OAuth、自定义兼容端点和 Ollama 本地模型;具体凭据和协议适用范围见对应章节 |
| **编程 Agent 管理** | Claude Code / Codex / OpenCode / Kimi Code 的安装、配置、更新与模型绑定,运行状态与终端输出查看 |
| **安全网关** | 即下文的「模型网关」,可选、默认关闭;仅对明确接入的编程 Agent 模型请求按策略检查、拦截或脱敏,支持的替换在响应中尝试还原,保护记录可查看 |
| **AI 大脑** | 结合终端上下文解释命令、错误和 Agent 方案,读取进展、整理结果与下一步;经 coding 模式和逐标签页授权后向受支持的 Agent 输入指令,在项目间交接任务、上下文和结论 |

**完整终端**:支持 macOS / Windows,保留 zsh / PowerShell、shell 配置、alias、脚本与现有命令行工具,提供独立 PTY、多标签页、多窗格与聚焦模式。用户自己的终端操作不受 AI 工具白名单限制。

**其他现有能力同样属于产品**:本机多 Agent 协作、跨 Agent ToDoList、跨机协同、IM 渠道、浏览器远程访问、记忆、定时任务、联网搜索、图片输入、会话历史、用量统计、隐私审计、配置优化与自动更新等均保留。核心分类只表示展示重点,不改变任何能力的支持状态、订阅要求或授权边界;不属于核心也不等于实验性。Privacy First、快速、简洁高效仍是贯穿产品的原则。

以下继续按使用场景分成五组,列出完整能力,而非另一份核心能力排名。

**一、编程 Agent 管理与协同**

- **并行**:在不同 tab 里同时跑 Claude Code / Kimi Code / OpenCode / Codex,每个 tab 一条独立 PTY,真正并行
- **绑定与协同**:在聊天框里敲 `@` 选中任一运行中的 agent(或用 `/agents`)把它绑定为本会话的转发目标,直接派任务、追进度;一个 agent 的结论可以经对话接力给另一个 agent
- **看护与驾驶**:打开 coding 模式,kaya 主动盯着各 tab 里的 agent——等决策时提醒你、跑完空闲时替你读取结果并总结;经你逐项授权后还能代为向 agent 输入
- **交接与派发**:需要接力时把后续任务写进**跨 Agent ToDoList**,目标 agent 空下来时会先问你要不要执行,你点头后才派发,干完由 kaya 按证据验收闭环
- **远程实例**:同账号另一台设备上运行的 agent 也会出现在 `@` 菜单与侧栏(带设备名徽标),可以派活、收发授权卡
- **安装与管理**:Agents 管理中心后台安装 / 更新各家 agent,支持自定义命令名、按协议接入模型、配置优化

**二、模型与供应商**

- **统一模型库**:在「设置 → 模型」维护**供应商 → 模型**两层结构:一个供应商可同时带**对话 / Anthropic / OpenAI** 三种端点与一份模型清单、一份凭据;配一次,聊天、编程 agent、审计评估共用
- **200+ 供应商目录**:models.dev 蒸馏快照 + 内置覆盖层,选择即预填端点与模型清单;也可以「自定义」填任意 OpenAI 兼容端点;同一供应商可建多条账号
- **认证两态**:API Key 或 OAuth 登录;Kimi Coding Plan 走设备码,**OpenAI ChatGPT 订阅走浏览器 Authorization Code + PKCE**,token 与 ChatGPT 账号身份只存系统钥匙串;ChatGPT 订阅仅供编程 Agent 经网关使用,不供 kaya 自带 Chat 或审计 AI judge 使用
- **在线模型发现**:保存 key 或点「刷新」即抓一次该供应商的模型列表,失败时回退目录快照并标注「可能滞后」,手工增补的行不受影响
- **模型元数据**:每个模型可声明上下文窗口、输出上限、视觉三态、思考三态与思考档位(minimal / low / medium / high / xhigh / max)、视频 / 音频输入能力;这些声明会按各家支持面投影到 agent 的原生配置
- **模型网关(可选,隐私加固)**:默认关闭;开启并明确接入后,对应编程 Agent 的模型请求改走本机回环网关,按独立策略检查、拦截或脱敏,支持的替换在响应中尝试还原;真实 API Key / OAuth token 只存系统钥匙串与网关内存,**不落任何 agent 配置文件**。详见下文**「模型网关」**专章
- **配置优化**:让 AI 读取脱敏后的配置现状与绑定模型元数据,给出带出处的优化建议;勾选后一次性授权写入、写后读回校验、失败自动回滚
- **用量统计**:聊天与网关共用的 Token / 请求记账,按模型 / Agent 分组、按天 / 周 / 月分桶(零内容)
- **云端 Token 用量(可选)**:「设置 → 账户」里的独立上传卡,默认关闭,确认 `kaya-usage-upload-v2` 同意清单后才开启;只上传 UTC 聚合用量桶与设备注册所需的随机设备 id、OS 家族、kaya 版本、consent 版本,不上传对话或工具内容

**三、隐私与可审计**

- **五道关卡**:用户输入 guard → policy gate → safety gate → execute 隔离 → output scrub,每一道都在本机完成
- **默认看不到文件正文**:只有你主动放进 `~/.kaya/` 的文件才能被读
- **网关脱敏 + 隐私保护统计**:逐命中的令牌化 / 告警 / 还原明细只落本机,可在设置里筛选、搜索、清空
- **审计回放**:已接入审计来源的会话逐条 JSONL,支持规则回放 + 异常规则 + AI judge 三层评估
- **记忆只在本机**:Agent 按证据自动写入 / 强化 / 归纳 / 归档,没有待审队列;你可以事后查看、编辑、回滚或彻底删除

**四、协作通道**

- **IM 渠道**:飞书 / Slack(企业微信入口待开放)长连接直连,不需要公网 IP;同一套隐私 pipeline,授权卡在 IM 里可批;可选把桌面聊天镜像到 IM
- **远程访问**:从浏览器看和操作这台设备上的 kaya,中转只透传、不落盘
- **跨机协同**:同账号两台设备互相派活,执行端准入 fail-closed,授权双端可批、权威在执行端
- **定时任务**:按间隔或每天定点自动发起回合

**五、AI 大脑与日常开发助手**

- **代码解释**:贴一段报错、一段 shell 脚本、一个正则,让 AI 解释它在做什么
- **环境检查**:查看当前系统信息、磁盘使用、运行中的进程、网络端口等
- **文件查询**:列出目录内容、统计文件大小、查找匹配的文件名
- **命令构造**:让 AI 帮你拼出 `find` / `sed` / `sort` 等组合命令,由 AI 在隔离子进程里执行白名单内的命令并把结果拿回来
- **日志和错误解读**:让 AI 解释一段错误输出,定位可能的原因
- **真实终端**:多标签 + 分屏 + 聚焦,PTY 会加载你真实的 `.zshrc` / PowerShell profile

kaya **不适合**也不试图做的事:

- 让 kaya 自带的 AI 工具直接改写你电脑上的源代码(在 tab 里跑编程 agent 写代码是另一回事——那是 agent 自己的能力,全程在你的终端画面里可见、可中断)
- 在你没有明确授权的情况下改写编程 agent 的配置文件(配置优化的每一次写入都要你在卡片上勾选并授权)
- 在没有你确认的情况下执行破坏性操作(如删除文件)
- 让自带的 AI 在你的终端里跑交互式程序(如 `vim`、REPL)
- 在没有你的允许下访问 `~/.kaya/` 之外的任意文件正文
- 替你回答编程 agent 弹出的确认——那是 agent 自身的安全闸。未经你逐项授权时 kaya 不会代答;你授权后(coding 模式)的代为输入也由多重复验把关,且决策始终由你本人做出

关于「谁来执行」:kaya 的 AI 会在**独立子进程**里执行白名单内的命令,把 stdout / stderr 直接展示给你,不需要你复制到终端再跑一遍;破坏性、交互式、系统修改类命令则在执行前就被拦下。你在终端里**自己输入**的命令不经过任何关卡——那是你自己负责的区域。两者共同的原则不变:AI 是协助者,决策与授权始终在你手里。

## 隐私与安全边界

隐私是 kaya 的**第一优先级**。下面是默认情况下你能期待的边界。

**默认 AI 看不到的内容**

- 你电脑上的任意文件**正文**:`cat`、`head`、`grep`、`less` 等读取命令默认不可用
- 你电脑上的系统环境变量:`env`、`printenv` 默认不可用

**默认 AI 可以查询的**

- **元数据**:目录列表、文件大小、修改时间、当前用户名、当前系统版本等
- 你终端里的输出内容(便于你让 AI 解释一段报错);读取结果过脱敏
- **运行中 agent 的定位与活动摘要**(在哪个 tab、什么目录、最近在做什么),以及它当前屏幕内容的尾部
- 你的任务清单(只读 + 受控创建)与跨 Agent ToDoList(AI 可查看、可在需要交接时创建任务,但执行时机由你决定、状态流转由 kaya 校验执行)
- 定时任务(可创建 / 启停 / 删除,和设置页里的同一份数据)
- **已生效的记忆**:核心规则 / 事实与记忆索引(自动裁决、可事后管理);归档冷存与已被取代的条目不进默认注入与检索
- 你主动复制或粘贴到对话里的文本与图片

**默认 AI 拿不到的**

- 文件的**正文**(除非文件在 `~/.kaya/` 里)
- 系统环境变量
- 归档冷存与已被取代的记忆条目:默认不注入、不检索;模型显式带 include_archived 检索时可读到(归档的**规则**是例外 —— 规则一律不进检索池,只能在 设置 → 记忆 里找回)
- 未经执行端准入和对应权限允许的跨机执行、按需读屏与对话中转;发现和状态摘要另有边界,见「跨机协同」
- 你的 API Key / OAuth token 原文(前端结构上就拿不到)

你在终端里自行输入的命令不经过 AI 工具的策略或安全检查;但终端输出可以被 AI 的只读工具读取,经脱敏后随对话发给当前模型。「不拦截你的命令」不等于「终端输出不会进入模型上下文」。

**`~/.kaya/` 可信目录**

如果你需要 AI 帮你读取某个文件的内容,把文件放进 `~/.kaya/` 目录下,然后告诉 AI 文件路径。这是唯一允许 AI 读取文件正文的位置。详见 [让 AI 读取文件](#让-ai-读取文件)。

可信目录并非任意读写区:凭据、网关、模型库、配置快照及用量上传状态等控制面还有额外的拒写或敏感拒读规则,桌面、IM 与跨机工具的读取范围也不同。完整边界见[隐私设计文档](PRIVACY.md)。

**脱敏是防线,但不是绝对保证**

在你输入文本、AI 读取文件、工具执行返回结果时,kaya 会自动识别并替换掉常见的密钥、PEM 私钥、身份证号、手机号、信用卡号等敏感信息。脱敏有 30 多类规则,涵盖常见场景。但 kaya 不承诺能识别**所有**可能的秘密——你不要把真正重要的密钥贴进任何 LLM 应用。

**云端 Provider 会收到什么**

当你在对话里发送消息、让 AI 调用工具时,经过脱敏的对话文本和工具结果会发送到你**在顶栏模型切换器里选的模型**(内置模型 / 我的模型):

- **内置模型(默认,yunhou `/chat` 代理)**:脱敏后的内容经你的登录令牌(JWT)发往 **yunhou 第一方服务器**,由服务端持 DeepSeek key 代答。kaya 客户端在发送前会按服务端限额裁剪(消息条数 / 每条字节 / 总字节上限,超限丢弃最早的历史消息)。登录令牌(refresh_token)只存在系统钥匙串(macOS Keychain / Windows 凭据管理器)。顶栏模型切换器的「内置模型」可展开为服务端模型目录:默认「跟随默认」(不钉死模型 id,跟随服务端默认运营调整),也可点选目录里的具体模型;目录不可用(未登录 / 无权限 / 未启用)时退回单行静态条目。
- **OpenAI 兼容(自备 key)**:脱敏后的内容发往你选择的 LLM 服务商(DeepSeek / OpenAI / OpenRouter 等),随你的 API Key 鉴权。
- **Ollama(本地)**:推理与对话 / 工具内容不外发(见下)。

kaya 不会向未列明、未授权的目的地发送你的内容。除上述模型端点外,你明确启用的 **Tavily 联网搜索**、**IM 渠道与镜像**,以及**远程访问 / 跨机协同所用的 yunhou relay**,也会按对应功能传输经脱敏的内容;这些路径均在相应章节列明。本地 UI 状态、会话、审计和应用日志都只保存在你自己的电脑上,不自动云同步;登录后的使用情况心跳与经明确同意的云端 Token 用量上传是独立通道,不上传对话或工具内容。

**API Key 与 OAuth 凭据怎么用**

你填在设置里的 API Key **只保存在本机系统钥匙串**,仅随请求发给你配置的模型端点 —— 不上传到 Yunhou,也不写入审计日志。kaya **不会**把你的 API Key 发给任何其他方。**不**承诺"完全不上传"——任何联网请求都需要鉴权,鉴权就需要 key。

macOS 上 kaya 的全部 secret(登录令牌、BYOK key、OAuth token、Tavily key、IM 渠道凭据)收敛为一个统一钥匙串条目,常规启动最多授权一次;首次启动需要把旧条目迁移进来,可能还会访问一次旧条目。回退到旧版本 app 时旧版读不到新存储,表现为「未配置」,需要重新录入(数据没丢)。Windows 上维持凭据管理器原有布局。

供应商 OAuth(Kimi Coding Plan)的 token 同样只存钥匙串:前端结构上拿不到 token 原文(IPC 返回里根本没有这个字段),真实 bearer 只在 Rust 请求路径与网关内存里使用。OAuth 供应商的每个启用端点必须与目录声明的**同一个 host** 一致,否则凭据不会被发出去——即使有人把库里的 base_url 改到别处。「退出登录」只清本地凭据,不会通知服务端。

**编程 agent 的流量(可选):模型网关**

聊天侧和编程 agent 侧是两条**独立**的出站路径:

- **聊天侧**:你选的模型走原生 API(内置模型 / 我的模型),内容过五道关卡;kaya 不会把聊天改道到网关。
- **编程 agent 侧**:默认由 agent 自己直连供应商(你不接入就完全不碰它)。一旦在 Agent 详情页打开**「经网关接入」**,它的模型流量就改走本机回环网关:`127.0.0.1` 上的一次 HTTP 转发,出站前做可逆令牌化、入站响应里还原。真实 API Key / OAuth bearer 只存在系统钥匙串与网关进程内存,**不写进任何 agent 配置文件**。

网关的档位是独立的:默认 **strict**(只自动拦截具名 secret,普通 PII 不自动改写),可切 balanced / aggressive;聊天侧的用户输入恒 aggressive、工具输出默认 aggressive。逐命中的明细(哪条规则、命中什么原文、换成了什么令牌、被还原了几次)落在本机 `~/.kaya/gateway/privacy-events.jsonl`,可从**设置 → 网关 → 隐私保护统计**查看、筛选和清空——它只在本机,默认遮罩,不进 LLM 上下文、不进诊断导出,与**聊天审计日志**(存脱敏后的正文)是两套东西;**零内容**的只有网关自己的脱敏事件 `gateway-scrub`。完整说明见下文**「模型网关」**专章。

**离线推理: Ollama**

如果选择 Ollama 作为 Provider,所有推理完全在你本机上进行,推理与对话 / 工具内容**不会**外发。登录后的使用情况心跳与经明确同意的云端 Token 用量上传是独立通道,不受 Provider 选择影响。适合对隐私最敏感的场景。本地端点(Ollama / LM Studio / vLLM)允许不带 key。

**五道保护概览**

简单来说,你输入到输出的每一句话都经过:

1. **输入保护**:粘贴的密钥和长文本被脱敏和截断
2. **命令策略**:可执行命令被白名单限制,默认拒绝未知命令
3. **安全检查**:破坏性、交互式、系统修改类命令被拦截
4. **隔离执行**:AI 的工具调用在独立子进程中运行,不影响你的终端
5. **输出脱敏**:工具输出再脱敏一次才进入对话

## 模型库与供应商

**一件事只在一个地方做**:模型库在 **⚙ 设置 → 模型**,它是模型与凭据的**唯一编辑处**;顶栏模型切换器只负责「现在聊天用哪个模型」;「设置 → 编程 Agent」只负责「哪个 agent 用库里的哪个模型、要不要经网关」。

**两层结构:供应商 → 模型**

一条**供应商** = 一套凭据 + 可选的三协议端点(对话 / Anthropic / OpenAI)+ 一份模型清单。同一供应商下的多个模型共用一份 key,所以「一个 API Key 配一次,处处可用」;模型自己带各自的启用状态、上下文窗口、能力与思考档位。

**添加供应商**

1. 点「+ 添加供应商」,从 **200+ 家供应商目录**里选(models.dev 蒸馏快照 + 内置覆盖层,含 OpenCode Go 等),端点与模型清单会预填;目录是编译期内嵌的,查看它**不联网**。
2. 目录里没有的服务商选「自定义」,填它的 OpenAI 兼容端点即可(自托管 vLLM / LM Studio / 本地网关都走这条)。
3. **同一服务商可以建多条账号**(同端点、不同 key),各自命名,分别接入不同的编程 agent。

**认证方式**

- **API Key**:从服务商官网获取,保存后进系统钥匙串;库文件里**不存** key。
- **OAuth 登录**:Kimi Coding Plan 走设备码;**OpenAI ChatGPT 订阅走浏览器 Authorization Code + PKCE**(点「登录」→ 在系统浏览器批准 → 状态卡显示已登录,可重新登录或退出),token 与 ChatGPT 账号身份只存钥匙串,前端拿不到原文,退出登录只清本地凭据。OpenAI API / Anthropic 条目没有可启动的 OAuth 入口,Rust 侧 fail-closed。ChatGPT 订阅只用于四家编程 Agent 经网关的 Responses 适配,不供 kaya 自带 Chat 或审计 AI judge 使用;OpenAI 已完成 macOS 上 Codex 首请求、长历史续跑与全局接管裸模型验证,Kimi Coding Plan 的真机验收仍待完成。
- **本地端点免 key**:`localhost` / `127.0.0.1` 这类本地端点允许不带 key(Ollama / LM Studio / vLLM)。

**模型清单与在线获取**

模型清单不是死列表:

- 保存一个非空 API Key 后自动抓一次该供应商的模型列表;详情页也随时可以点「刷新」(旁边标着最近获取时间)。
- 首开一个「已在库但从未抓取过」的供应商也会抓一次;OAuth 未登录 / 过期时跳过,登录成功后补一次。
- **只按你的操作触发,没有后台轮询**;请求只发往该供应商自己的端点,key 只进鉴权头。
- **ChatGPT 订阅例外**:使用编译期静态模型目录,不发起在线 `/models` 请求或连通性探测。
- 失败时按固定原因提示(鉴权失败 / 网络 / 超时 / 响应过大 / 无可用模型等);带目录来源的供应商会回退展示目录快照并标注「可能滞后」——**手工增补的模型行不受影响**,也不会因为一次网络失败把已发现的模型删掉。

**每个模型能声明什么**

| 项 | 说明 |
|---|---|
| 启用 | 是否参与投影与选择器;停用的模型不会出现在 agent 的模型面里 |
| 上下文窗口 | 可填精确 token 数,也接受 `256K` / `1.5M` 这类简写(按 1024 进制);失焦或回车才提交,小于 1K 会被拒绝;留空 = 未知(按缺省处理) |
| 输出上限 | 单次生成上限,供需要该字段的 agent 使用;未知时用保守缺省而不是 0 |
| 图片输入(视觉) | 自动 / 支持 / 不支持。「自动」的判定顺序 = 供应商目录蒸馏(`modalities.input`)→ LiteLLM 快照。查不到时**聊天侧警告后仍允许发送**;投影给编程 agent 时按「不支持」处理(不声明 `image_in` 只是不能发图,声明错了会被上游 400) |
| 思考 | 自动 / 支持 / 不支持。**显式声明压过目录结论**,包括显式的「不支持」 |
| 思考档位 | minimal / low / medium / high / xhigh / max 多选 + 默认档;显式档位会投影到四家 agent 的原生键(kimi 的 `support_efforts` / `default_effort`、codex 的 `model_reasoning_effort`、opencode 的 `options.reasoningEffort`、claude 的 supported capabilities + effort level) |
| 能力 | 视频 / 音频输入可勾;图片输入由视觉有效值派生、工具调用恒开(两项只读)。该行目前由 kimi-code 消费 |

「清除声明」会把该模型行上的思考 / 档位声明一起摘掉(只摘布尔是不够的),回到按目录自动判断。

**改动如何扩散**

- 改供应商(端点 / 模型清单 / key / 能力)→ 已接入的 agent 配置**自动跟随**,不需要第二个动作。
- 清空 API Key → 网关里对应的凭据一并失效,依赖它的 agent 会退出网关形态(回落它自己的配置)。
- 删除供应商 → 与它接入的 agent 一并退出 kaya 的配置,并**删除该 key**(确认框会提示)。
- **没有接入的 agent 一律不碰。**

**状态与诊断**

- 左栏每个供应商一行状态点:内置模型看登录与订阅;自带模型看凭据与端点是否就绪(API Key 形态看有没有 key、OAuth 形态看有没有登录),并标注**哪些 agent 正在使用它**(只算真正经网关接入的)。
- 已支持的服务商(DeepSeek / Moonshot(`api.moonshot.cn` / `api.moonshot.ai`) / SiliconFlow / OpenRouter 等)显示该账号的**余额**(只读查询:key 只在本机读取并只随鉴权请求发给对应供应商,不经 kaya 中转、不写日志、不进审计;不认识的服务商不显示)。
- **「测试连接」**:任何 HTTP 响应都算端点可达 —— 2xx/3xx 是正常,401/403 是「可达但凭据可能无效」,超时 / 传输失败分别报。它**不验证模型能不能用**,也不写库。
- **「接入状态」**:逐 agent 显示「已接入」或「未接入 + 原因」(缺凭据 / 端点缺失或停用 / 协议不兼容 / 模型已停用)。网关没运行时显示「网关未运行,接入状态未知(凭据状态未检查)」,不会假装已检查。

## 模型网关

模型网关就是产品核心能力中的**安全网关**:可选、默认关闭,只处理明确接入的编程 Agent 模型请求,不接管聊天或系统全部流量。它按独立策略检查、拦截或脱敏,对支持的替换在响应中尝试还原,并提供本机保护记录;可用模型受 Agent 的协议与凭据范围约束。

**它解决两个具体问题**

1. **密钥不再落在 agent 配置文件里。** 没开网关时,要让 Claude Code 用你的第三方 key,只能把真 key 写进它的配置——那是一个明文的、会被云同步、会被别的工具读到的副本。开网关后,agent 配置里只有一串 per-agent 占位 token(`kayagw_…`)和一个别名;真 key 只在你机器的钥匙串和网关进程内存里。
2. **按策略减少敏感内容原样上行。** 网关对需要改写的命中使用**可逆令牌**,支持的响应替换再尝试还原。令牌尽量保持邮箱、手机号、身份证和银行卡等原始形状。默认 strict 不自动改写普通 PII,脱敏识别与响应还原也不承诺绝对成功。

**三步开启**

1. **⚙ 设置 → 模型** 里把供应商与模型配好(见上一章)。
2. **⚙ 设置 → 网关** 打开「启用网关」。状态行显示「运行中 · 端口」即就绪;网关只监听 `127.0.0.1`,不对外暴露。
3. **⚙ 设置 → 编程 Agent** → 某个 agent 详情页的**「模型网关」卡**:打开「经网关接入」并选「默认模型」。

新绑定默认就是经网关接入;如果网关还没启用,开关会提示「将在网关启用后生效」,不会静默失效。

**严格边界:只有「网关形态」和「撤除」两种状态**

这是理解网关的关键:

- 写入 agent 配置的永远是**本机回环地址 + 占位 token + 模型别名 `kaya/<别名>` + 友好显示名**(例如「Deepseek (deepseek-flash)」)。
- **真实 base_url 和真实 key 永不落 agent 配置。** kaya 也不会把库里的模型「直连」给某个 agent——没有第三种形态。
- **占位凭据不能用于上游鉴权**:注入真实凭据后,鉴权头里的 `kayagw_` 会触发拒发;供应商声明的自定义头还会拒绝 `kaya/` 别名。内容请求的顶层模型别名会转换为真实模型;元数据直通请求可能保留可解析别名,不应理解成所有请求正文都检查并删除别名,详见隐私文档 §7.11。
- 关闭开关 = **撤除** kaya 写过的配置(按接管前快照逐键恢复),不是「改回直连」。

**全量目录与按协议选路**

- 网关的目录是**模型库全量**(provider × model),按 **Anthropic / OpenAI Chat / OpenAI Responses** 三协议切片展开;`/v1/models` 由网关自己回答,所以 agent 内的模型选择器能看到库里所有可用模型,而不只是你绑定的那一个。
- 每个 agent 的协议族是固定的:Claude Code 走 Anthropic;**Kimi Code / OpenCode 走 Chat 兼容**;Codex 走 Responses。
- **OpenAI ChatGPT 订阅**使用官方 Codex Responses 上游:Codex 原生 Responses;Kimi Code / OpenCode 的 Chat 与 Claude Code 的 Anthropic Messages 由网关反向适配成 Responses,四类 agent 可共享同一订阅凭据;缺账号身份一律 fail-closed。
- 供应商只有 Chat 端点时,给需要 Responses 的 Codex 自动追加一条 **Responses→Chat 适配**切片(目录里会标「Responses→Chat」),上游 4xx/5xx 的错误形状会回译成 Responses 的形状。
- **fail-closed**:请求里的模型名不是可解析的 `kaya/<别名>`(裸上游模型名、畸形名、跨族别名)一律 **HTTP 400**,错误体带原因、指引和文档链接,**绝不偷偷转发出去**。唯一例外是显式开启「全局接管 codex」且绑定 ChatGPT Responses 时,Codex 可切换官方内置裸模型名;普通 profile、其它供应商和第三方工具仍拒绝裸名。`/health` / `/healthz` 免 token 本机自答,方便探活。

**接管与恢复:不会弄丢你的原配置**

明确接入后,kaya 接管的是 agent 的**模型面**——provider 块、kaya 模型条目、默认模型指针、picker / catalog 清单、opencode 的 provider 门。它**不碰**权限设置、hooks、MCP、插件,也不碰「配置优化」管的那批键。

- 接管前会把这些键**逐键快照**到 `~/.kaya/agent-config-snapshots/`(0o600)。
- 「接管时已存在」的非 kaya 模型 / provider 条目会先快照、再移除或隐藏;接管之后你新增的条目保留。
- 撤除时按「只补缺失、当前同名条目优先」合并恢复,不会覆盖你后来自定义的条目。
- 快照拍不下来(读失败 / 锁忙)时,kaya **不删、不覆写**那些恢复不回来的用户值,只写自己的命名空间并留痕——宁可不接管,也不做不可逆删除。
- **漂移**:如果配置文件被 kaya 之外的工具有效修改,详情页会显示「配置在 kaya 之外被修改」,kaya 不自动覆盖,点「重新接入」按期望形态重写。
- **Codex 默认隔离**:kaya 只写自己的 profile(`codex --profile kaya`),影响从 kaya 启动或显式选该 profile 的 Codex。打开**「全局接管 codex」**才会写官方 base 配置,影响裸跑 codex 与 ChatGPT 桌面版拉起的会话——有二次确认,停止网关 / 退出 / 崩溃都按快照恢复。
- **「只显示绑定模型」**:开启后该 agent 的模型选择器只显示绑定模型;关闭则显示库里全部可用模型。
- **撤除是幂等的**:第二轮撤除只收尾、不会把上一轮恢复出来的用户 `base_url` / token 再删一遍。
- **边界(如实说明)**:在有快照机制之前(更老的版本)接管过的配置没有快照,撤除只能退化为「只摘 kaya 写的键」,接管前的旧值需要你手动恢复。

**脱敏:网关独立档位**

| 档位 | 行为 |
|---|---|
| **strict(默认)** | 只自动拦截具名 secret,普通 PII 不自动改写 |
| **balanced** | 具名 secret 与 PII 令牌化,高熵兜底**只告警** |
| **aggressive** | 最狠:高熵字符串也令牌化(误伤更多编码数据,还原可靠性下降) |

- 网关档位**独立于聊天**:聊天侧用户输入恒 aggressive、工具输出默认 aggressive(通用页可调)。
- 令牌尽量**保持形状**:邮箱、手机号、身份证(18 位且重算 GB11643 校验位)、银行卡(保留分隔符、重算 Luhn)、JWT 等。
- PEM 私钥**整块**匹配(BEGIN + body + END),不会被切碎。
- **按协议字段处理**:具名 secret 始终令牌化;代码、工具参数与结果里的形态 PII / 高熵内容默认只观察不改写,避免破坏函数参数、JSON 与 `tool_call_id`。
- **精确媒体校验**:合法 PNG / JPEG / GIF / WebP / PDF / WAV / MP3 二进制原样转发,包括 Responses 工具输出中的标准图片 / PDF 部件和 Chat / Responses 的音频部件;`text/*` 载体按文本处理。不支持的媒体、声明冲突或校验失败会返回 400 且不转发上游,异常嵌套和额外业务字段仍经过隐私扫描。
- **公开文档示例**:AWS 官方文档中的完整公开 access key ID 示例不会被当成真实密钥替换;相似值仍受保护,显式用户令牌表始终优先。
- 公开协议 ID(`call_` / `toolu_` / `tool_` / `fc_` / `resp_` / `msg_`)在高熵兜底里豁免(否则会把工具调用 ID 涂掉),但**具名规则照常扫**。
- **用户令牌表**:写死替换规则——出站把「真值」换成「令牌」,响应原样还原(例如把真名 `张伟` 换成 `person-a`)。适合「这个项目里我不想让模型看到真名 / 内部代号」这类需求。
- **「拒绝未知路径」**是独立开关:默认透传未识别的 API 路径并记告警,开启后直接拒绝(可能打断 agent 的辅助请求,所以默认关)。
- **还原不是绝对的**:回包里**已知令牌**会自动还原,但模型如果把令牌改写 / 拼错,就无法保证还原。这是可逆令牌化固有的取舍,不是缺陷。

**隐私保护统计(逐命中明细)**

设置 → 网关 顶部的子 Tab「隐私保护统计」:

- 默认展示全部规则记录,**未替换的风险记录排在最前**,再按规则置信度排序,已替换记录最后;顶部概览先看风险,不等逐条请求流水。
- 动作用直白的「已替换 / 未替换」表示;详情分别说明出站替换与响应还原,**响应还原次数只统计实际记录到的还原**,未替换不直接宣称已泄露。
- 可按类别、动作、Agent、模型路由、规则类型、时间窗筛选;可按原文或令牌搜索;类别 / 动作标签点一下即按该标签过滤。
- 同一请求里同内容的命中会合并并累计**出现次数**,展示首次 / 最近出现时间和原始记录数。
- **明细含命中原文与替换后的令牌**,只存本机(`~/.kaya/gateway/privacy-events.jsonl`,0o600),默认遮罩、点行才展开,不自动进 LLM 上下文或诊断导出;展开区展示原始时间戳、记录 ID / 请求 ID,并可打开原始 JSONL 核验。
- 界面读最近 90 天、最多 5,000 条;可「清空当前视图」或「清空全部记录」(带二次确认)。
- **请求指标与最近事件**另记请求数、改写请求数、上游 4xx、精确恢复和媒体处理;逐条请求审计默认折叠,只用于排查,每条 Content 类请求只保留结构化计数与状态,不含正文、令牌或完整字段路径。
- **兼容诊断**:签名推理因协议完整性被本机拒绝时,另存本机零内容事件,可通过固定日志路径与命令核验;只记请求 ID、字段定位和决策等结构化信息,不含原文、令牌或签名正文,不上传也不进诊断导出。全量清空会连带删除兼容事件,选择性清空不动;关联日志清理失败会明确提示部分失败。
- 这与**零内容的网关脱敏事件** `gateway-scrub` 是两套独立存储:后者记「发生了什么类别的事件」,隐私明细记「具体替换了什么」。聊天审计日志是第三样东西——它存脱敏后的正文。

**上游异常的兜底**

- **流式**:连续 120 秒(默认值,可在网关配置里调整)没有数据就中止,并按 agent 使用的协议发一帧**终结错误**(Anthropic `event: error` / Chat 错误 chunk + `[DONE]` / Responses `response.failed`),**绝不伪造完成**——agent 侧表现为一次失败请求,由它自己的重试接管,而不是无限挂死。
- **非流式 / 等响应头**:各有 300 秒上限,超时按结构化 504 回。
- 超时 / 断流会写入 **App 诊断日志**(设置 → 日志与调试),只记路由标识与秒数,**零内容**;网关页不展示这两项计数。

**它不做什么**

- 不改写聊天流量:聊天直连你选的模型,不走网关。
- 不存你的请求内容:网关审计零内容,隐私明细是独立的本地存储。
- 不做透明代理:未纳入模型库的模型会被拒(HTTP 400 带指引),不会偷偷放行。
- 不接管 agent 的非模型配置(权限 / hooks / MCP / 插件 / 优化配置都不碰)。
- **不允许多开抢占**:dev 与 prod 两个实例的网关互斥,同一时间只有一个实例持有;被占用时写操作会被拒绝并说明是哪个实例在占用。

**用量**

聊天与网关共用同一套 Token 记账。**设置 → 模型 → 用量统计**可以看窗口期的 Token / 请求总量、按模型与按 Agent 的合计,并按天 / 周 / 月分桶、按 Agent 过滤。它只记供应商 / 模型 / Agent 标识与实际计数,不记请求正文;上游没返回 usage 时不编造。独立于 agent loop 的辅助调用(快速决策 / 任务提炼 / 记忆巩固)不计入;入口路由判定本身也不计,它触发的瘦身回合照常计入。

## 完成第一次对话

配置好后,在左侧对话窗口底部输入框里输入:

```
查看当前系统版本和 CPU 架构
```

按 **Enter** 发送。你会看到:

1. AI 先展示一段折叠的思考过程(当前模型支持并启用了思考时)
2. 然后出现一张**工具卡片**,显示 AI 调用了哪个工具、传了什么参数
3. 卡片状态从 **运行中** 变成 **已完成**,展开可看完整 stdout / stderr
4. AI 把结果整理成自然语言回答

回答跟随你当前消息的语言,明确要求的语言优先；英文界面中无法判断时默认英文。工具卡保留实际工具输出的原文。

**识别三种元素**

- **思考区**:可折叠的灰色背景段落,展示 AI 的推理过程
- **工具卡片**:每次 AI 调用工具都会出现,显示工具名、参数、运行状态、输出
- **最终回答**:AI 的自然语言结论

如果结果不是你想的,可以继续追问:

```
磁盘空间使用情况呢?只关心当前用户的文件
```

如果 AI 卡住或答得不好:

- 按 **Esc** 或点击 **⏹** 按钮中断当前回合
- 然后换个问法重新开始

**粘贴图片**

在对话输入框按 **⌘V**(Windows:**Ctrl+V**)可以粘贴图片:kaya 会自动剥除照片的 EXIF / GPS 等元数据,长边过大的图自动降采样。每条消息最多 4 张、每张不超过 5MB,支持 png / jpeg / webp / gif。图片只随消息发给你选择的目标模型:自带模型(BYOK)且该模型支持图片输入时才会发出;在 **设置 → 模型** 里,每条模型可声明「图片输入:自动 / 支持 / 不支持」,「自动」按目录蒸馏 → LiteLLM 快照的顺序判定;内置模型暂不支持看图,带图发送会被拦下并提示。图片本身是内存态:不落盘、不进审计内容,只记 mime 与字节数。已发送消息里的图片有「发送给 agent」按钮,可以把图片以 0o600 暂存到 `~/.kaya/tmp-images/` 并把**绝对路径**交接给终端里正在运行的编程 agent(agent 需自行支持读图)。图片不跨会话保留:开新对话后,历史消息里的图片显示「已随会话清除」占位。

**使用技巧**

对话区会展示 Kaya 使用技巧:空对话时是欢迎卡片,有消息后是输入框上方的单行提示条,每 5 分钟自动轮换一条;已用过的功能对应的技巧会自动降优先级。点「换一条」立即换下一条,点「不再提示」永久关闭。

## 对话内 slash 命令

在对话输入框敲 **`/`** 会唤出命令菜单(键盘上下选择或鼠标点击补全),也可以用 `/help` 随时列出所有命令说明。内置命令:

- **`/agents`**:列出当前正在运行的协同 agent(kimi / claude / opencode / codex 等)。点击卡片把它绑定为**本会话**的转发目标——绑定是会话级的,新对话自动清空
- **`/new`**:新建对话(与顶栏的新建按钮是同一入口)
- **`/sessions`**:从审计记录列出历史会话,点击卡片查看只读的历史内容
- **`/memory stats`**:查看记忆库的统计与健康状态
- **`/compact`**:把当前会话的上下文压缩成一份摘要继续对话(可见的聊天记录保留不变);压缩前会先自动提炼一次记忆,重要信息不会因压缩丢失
- **`/help`**:列出全部命令及说明

在对话输入框敲 **`@`** 会唤出当前运行中的协同 agent 列表(可与 `/agents` 一样继续输入过滤——名称、实例 ID、项目标签、工作目录都能命中,名称与项目命中时优先显示),菜单每项第二行显示该 agent 的状态、工作目录与活动摘要;键盘上下选择或鼠标点击即把该 agent 绑定为本会话的转发目标,并把可辨识的组合标签(`@实例ID · 项目(目录)`)带入输入框——你能直接看到这条消息将发给谁,之后的消息经既有绑定通道转给该 agent,无需先打开 `/agents`。

以 `/` 开头但不是内置命令的输入(如 `/auto`)不会报错:如果当前会话已绑定 agent,kaya 会把原文写入该 agent 所在终端的输入行并回车——相当于替你敲给它。写入前做 fail-closed 复验(pane 仍存活、前台仍是绑定的那个 agent、不在等待菜单中),任一不满足就不写入。这类转发**不消耗 LLM 回合**,转发记录会以卡片形式进入消息流并记入审计。跨 tab 换绑时,kaya 会在你下一条消息里附带一条一次性上下文便签,让 AI 知道换绑的来龙去脉(便签发给 kaya 的 AI,不会直接写进 agent 的终端)。

## 任务清单(Task)

kaya 内置一个轻量任务清单,帮你和 AI 一起跟踪要做的事:

- 顶栏的待办开关打开 **任务面板**,可以查看、勾选、管理当前任务
- 在对话里用「添加任务 …」「修改任务 …为 …」「删除任务 …」「清空任务清单」这类指令可直接管理清单:这类指令由**客户端本地识别并执行**,不经 LLM;自由表述(如「帮我把买牛奶标记为完成」)不会被识别为指令,会作为普通消息发给 AI。「提炼任务」指令则让 AI 草拟任务、经你确认后入清单
- 暂时不做的任务可以**归档**:归档后从主列表和计数中隐藏,收进面板底部的「已归档」折叠区,可随时恢复;归档任务不会出现在 AI 看到的清单快照里
- AI 侧的工具是**只读 + 受控创建**:它随时能看到清单快照对齐上下文;你让它建任务时(如「帮我建个待办:买牛奶」)它可以创建——标题经客户端校验后落库,同名未完成的任务自动跳过;但它不能替你勾选完成、删除或归档

## 跨 Agent ToDoList(agent 间交接)

任务清单记的是**你的长期待办**;跨 Agent ToDoList 记的是**要交给运行中 agent 执行的任务**——两者是两个独立实体,互不影响:

- **解决什么问题**:跨 Agent 保存上下文 + 找时机执行。一个 agent 干完当前工作、后续步骤需要**另一个 agent** 配合时,AI 会把任务(标题 + 交接上下文)写进 ToDoList,上下文随条目保存,换会话、重启应用都不丢
- **什么时候执行,由你决定(默认)**:目标 agent 闲下来时,对话里的 AI 会问一句「现在执行吗」,你明确同意了才真正派发——kaya 最了解每个编程 agent 当前的状况,所以由它来挑时机问你;你也可以随时在条目上手动点「派发」。想更省事可在 设置 → 模型 把「指令确认」切到**自动模式**:时机成熟时 kaya 直接派发、不再逐次询问(终端写入的授权卡体系不受影响)
- **agent 自己干完了,kaya 看得见**:kaya 会持续留意每个运行中 agent 的活动;当目标 agent 闲下来时,它会先对照屏幕证据核查队列里的任务——发现 agent 已经自行完成某条任务,就直接把该条目标记完成并告知你,不会再重复派发;发现它正在做,也不会催第二次
- **已经在干的任务,状态实时是「执行中」**:如果任务其实已经交代给目标 agent(比如 kaya 经终端写入直接派活)后才补建条目,或条目的目标 agent 恰好开始忙活,kaya 观测到后会立即把条目从「待执行」转为「执行中」并接管后续的验收闭环,不再停在「排队中」;agent 干完闲下来后照常验收。同一 agent 同时开着多个实例时 kaya 分不清该跟哪一个,这种条目维持待执行、不自动接管
- **展示位置**:Chat 输入框上方的 **To Do List 区**,默认收起,点一下展开就能看到这些待执行条目与它们的状态;已完成的条目收进底部「已完成」折叠区留痕(完成时间、结论与证据,最多保留 50 条,可一键清空);展开态还有「汇总进展」按钮,让 AI 读屏后把各仓库进展汇总成一份报告发到对话里
- **状态四种**:待执行 / 执行中 / 已完成 / 失败。完成不再「验收通过即删除」——完成后条目移入「已完成」区持久留痕;失败的条目保留并附上结构化原因(执行失败 / 感知不明 / 目标已退出 / 环境受阻),AI 会向你说明,你可以按原因点「重试」「重新观察」「标记完成」「重派」或删除
- **感知闭环**:agent 报空闲 ≠ 任务完成。空闲后 kaya 会发起一轮**感知回合**(观察与验收合一),对照三类证据判定:kaya 自采的 git 只读摘要(分支 / 未提交改动 / 最近提交,内容经脱敏)、目标 agent 的活动台账、终端屏尾。结论分五种:已完成 / 仍在推进 / 执行失败 / 证据不足 / 与本任务无关——证据不足不再算失败,只有连续多轮看不明白才收敛为「感知不明」,你可以人工确认标记完成
- **目标不明先问你,不创建含糊任务**:kaya 是任务的「总指挥」——需求没说清(目标或验收标准缺失)时,它会先在对话里向你质疑、确认,澄清后才把任务写进 ToDoList,避免 agent 朝着有偏差的目标白跑
- **执行失败先归因,不硬重试**:确认执行失败时 kaya 会先读屏归因(任务不清 / 派发走样 / agent 卡住 / 环境问题),失败条目上能看到归因与补救建议;自动模式下(「任务不清」除外)kaya 会带着归因自动重试一次,仍不成就停下来等你;归因是「任务不清」时它会直接告诉你缺什么信息,你补充后它重建一条清晰的任务再排队
- **kaya 的编程规范**:总指挥有自己的工作规范(小步快跑 / 改动带测试 / 验收要证据 / 失败先归因),它创建和验收任务时都会遵循;你可以在 `~/.kaya/methodology.md` 写入自己的规范覆盖它(规范内容会随对话发给模型,请勿写入机密信息)
- 派发仍走既有的授权体系:coding 模式总闸 + 该 tab 的授权卡缺一不可——但不再卡在授权上:点「派发」时若该 tab 尚未授权终端写入,kaya 会顺带弹出授权卡,你点「允许」后任务自动派出,不用再来回操作。ToDoList 内容只存在本机,随应用重启保留;重启时进行到一半的任务会安全地回到待执行,不会丢失

## 使用终端与标签页

**基本终端操作**

右侧是你真实的 shell:macOS 上是登录 zsh(加载你的 `.zshrc`,别名 / 环境变量 / conda 与原生终端一致);Windows 上是 PowerShell(优先 pwsh 7,未安装时退回系统自带的 Windows PowerShell 5.1;git-bash 用户设置的 `$SHELL` 会被尊重,走原 POSIX 路径)。常用操作:

- 输入命令后按 **Enter** 执行
- 鼠标选中文字按 **⌘C** 复制,**⌘V** 粘贴
- 滚动条或触摸板向上滚动查看历史输出

你在终端里输入的命令**完全属于你自己**,AI 不拦截也不审核——这是你为自己负责的区域。

**多标签页**

kaya 支持同时打开多个终端,每个标签页是独立的 shell 会话:

| 操作 | 快捷键 |
|---|---|
| 新建标签页 | **⌘T** |
| 关闭当前窗格 / 标签页(焦点在终端时) | **⌘W** 或标签上的 × 按钮 |
| 切换到第 N 个标签页 | **⌘1** 至 **⌘9** |
| 上一个标签页 | **⌘⇧[** |
| 下一个标签页 | **⌘⇧]** |
| 重排标签页(焦点在标签栏时) | **⌥⌘←** / **⌥⌘→** |

每个标签页有自己的工作目录、命令历史和滚动历史。关闭标签页时,标签页内的命令历史会自动合并回全局历史(macOS 上合并到 `~/.zsh_history`;Windows 上每个 tab 的历史走 PowerShell 的 PSReadLine 历史,关闭时合并到 kaya 自管的全局历史文件,不污染你的 shell 历史)。

**字体大小**

- **⌘=** 或 **⌘+**:放大 1px
- **⌘-**:缩小 1px
- **⌘0**:重置为默认大小

**关闭确认**

关闭标签页(**⌘W** 或 × 按钮)和关闭整个 kaya(左上角红色 ×)都会弹出确认对话框,防止误操作丢失未保存的工作。

**⌘Q 不弹确认**

使用 **⌘Q** 退出时,macOS 不显示确认对话框,但 kaya 会先尝试把本地各标签页的 shell 历史合并到 `~/.zsh_history`,然后再退出。尽量别用 ⌘Q,推荐红 X 或菜单退出。

**断开的标签页**

如果标签页因为网络或进程异常断开:

- 标签状态显示为灰色
- 打开 **⚙ 设置** → **通用** 标签页的 **Shell** 小节,点击「立即重连」重连该会话对应的 PTY

**tab 等待确认提醒**

当某个 tab 里运行的 AI CLI(kimi code / claude code 等)弹出需要你决策的确认(如命令审批)时,kaya 会主动感知并把决策收口到对话输入框,而不需要你自己盯着终端:

- 对话窗口出现一张通知卡片,显示哪个 tab 的哪个 AI 在等待、确认内容摘要;卡片上只有「忽略」(确认内容变化会重新提醒)
- 对应 tab 上显示一个提醒角标
- 最近一张待决的确认如果带选项菜单,会以决策条常驻在对话输入框上方:显示决策文案、各序号对应的含义,并提示「输入数字选择」
- 你直接在对话输入框敲菜单序号并发送,kaya 会把对应按键写回该 tab 里的 AI CLI。写回前会做多重复验:tab 仍存活、前台进程仍是受支持的 AI CLI、该菜单仍显示在画面中、序号在合法范围内——全部通过才允许写入,且只接受菜单上的个位数字序号
- 序号越界、输入的不是裸数字、或当前没有待决确认时,输入不会被拦截,照常被当作普通消息发送
- 你在终端里处理完后,卡片自动变为「已处理」

kaya 永远不会替你回答 AI CLI 自己的确认——那是它自身的安全闸,决策始终由你本人做出。

**coding 模式(主动看护编程 agent)**

打开顶栏的 coding 模式开关后,kaya 会主动盯着你运行在 tab 里的编程 agent(Claude Code / Kimi Code / OpenCode / Codex 等),不需要你自己盯着终端:

- 检测到对方**弹出确认、等待你决策**时,kaya 自动发起一个对话回合,转达对方需要什么决策并询问你的指示
- 检测到对方**任务跑完(画面空闲)**时,kaya 主动读取结果、总结进展并询问下一步
- 监控是**只读**的:kaya 只报告和询问,永远不会替你点确认——决策始终由你做
- 这个开关同时是「驾驶」的**总闸门**:只有开关打开,对话端才具备向编程 agent tab 发指令的能力(仍需每个 tab 单独的授权卡确认);开关一关,该能力**从下一回合起**整个下线(工具不再注册;正在进行的回合按回合开始时的状态走完),监控不受影响的部分只剩被动的通知卡片与 tab 角标
- 自动回合携带的确认内容摘要经过脱敏;每个 tab 有 60 秒冷却,对话进行中不打扰(回合收尾后补发)
- **智能调度(v2.4.0 起)**:kaya 转发 / 派发指令前会先评估目标 agent 的实时状态(在忙 / 空闲 / 在等你确认 / 正在做什么);指令一律照常写入,但结果会附带状态提示——目标在忙时提示「将排在当前工作之后」,60 秒内重复发送相同指令时提醒你可能无需重发;指令写入后 kaya 还会读屏确认它真的被提交,滞留在输入行时会自动补发一次回车
- kaya 掌握每个运行中 agent 的定位(所在目录、项目标签)与最近动态,你问「它做到哪了」时,它会按需深读该 agent 的终端记录再回答——读取内容同样过脱敏管线
- **快速决策层(v2.3.8 起,默认开启)**:自动看护先过一道毫秒级语义闸——明确不值得打断的事件(如刚汇报过的重复空闲)不再发起回合;对方「正在运行」的瞬时状态也不再播报。简单提问(闲聊、一句话问答)走轻量回合,响应更快、更省额度。决策请求的接收方与对话完全相同(你选用的模型),发送前过同一条脱敏管线;可在 **⚙ 设置 → 模型** 关闭,立即生效
- 注意:coding 模式的自动回合会随对话发送给你当前选用的模型(与手动提问同一条外发路径);关闭开关即完全不触发

**运行中 agent 状态栏(coding 模式专属)**

coding 模式开启时,对话面板左缘有一条可开合的侧栏(点边缘的箭头把手展开 / 收起,开合状态会被记住;展开的宽度可以拖右缘把手调整;窗口太窄时它会变成覆盖在对话上的抽屉,不再挤压对话区;终端满屏时它仍然常驻在窗口左缘,同样可开合、可拖宽):

- 总览所有正在运行的编程 agent:每张卡片显示实例编号(如 `kimi-code #2`,编号全局递增、跨 agent 类型混编)、当前状态(等待你决策 / 空闲 / 运行中)与所在 tab、工作目录;运行中的卡片还会显示它正在做什么的摘要
- 卡片上还有一行**状态栏**:当前模型、思考档位、权限模式、context 用量(kimi code 四项全有;claude code 可显示模型、思考档位与上下文用量,并补充目录、worktree 和分支;codex 只有模型;opencode 有模型、模式(构建 / 计划)与思考档位,无 context 用量)。权限模式显示为「总是询问 / 按需询问 / 从不询问」等直白文案;宽度不够时只保留关键段,鼠标悬停可看完整内容
- 每个窗格(pane)可编辑一个**项目标签**(点卡片上的项目行直接改,按窗格持久化——同一 tab 的两个窗格可以各挂各的标签):多项目并行时用来辨认「这个 agent 在为哪个项目干活」,@ 列表和卡片上都会显示
- 点卡片一次完成三件事:切到对应 tab、把它绑定为当前对话的转发目标、聚焦输入框——之后直接在对话里对它说话即可,与 `/agents` 绑定同一条通道;同时 kaya 会让 AI 顺带读屏汇报一次该 agent 的最新进展(10 秒内重复点击不重复汇报;对话正忙时只提示、不插队)
- 「等待你决策」的卡片上直接列出对方的选项按钮,点一下就作答,不用切 tab
- 侧栏收起时把手上有数量角标;有 agent 在等决策时角标变警示色

**运行中实例配置与 Coding Agent 工作台**

运行中的本地 Agent 可以按**当前实例**编辑运行时配置:保存后先进入待生效队列,等该实例空闲并经身份复核后,通过它自己的原生控件生效,不重启 Agent、不修改全局默认配置。模型、思考强度、Permission 分字段执行并读回核验;实例已更换、仍在忙碌、等待决策或无法确认生效时不会写入。远程 Agent 只读。

当前开放范围以生效证据为准:**Claude Code** 支持模型 / 思考强度 / Permission;**Kimi Code** 支持模型 / 思考强度,Permission 暂不支持;**OpenCode** 支持思考强度 / Permission,模型暂不支持;**Codex** 的三项运行时字段目前均不开放。未接入模型网关的 Agent 只禁用模型字段,不妨碍其它已支持字段。

Coding + chat-focused 视图是三栏工作台:左侧为运行中 Agent,中间 Chat 是主交互入口,右侧只列等待决策与未决授权。普通忙碌/状态栏变化只更新本地卡片；主动开启 Coding 时汇报工作区整体状态，Agent 空闲或等待决策时合并为低频只读跟进，Chat 忙时延后。关闭模式、换会话或手动停止取消待发汇报；恢复持久化开关不重复整体汇报。切换视图或关闭 Coding 模式时 Chat 不会卸载,输入草稿与待发图片保留。

**Agents 管理中心**

应用菜单 → **Agents**(或点顶栏右侧的 Agents 图标)打开设置并直落**「编程 Agent」**标签页——编程 agent 的管理中心就在这里。安装、更新、模型配置也可以在对话里直接让 kaya 做(比如说「帮我装一下 Claude Code」)——两条路径背后是同一套引擎:

- **后台安装 / 更新**编程 agent:按可用方式依次尝试(npm > brew > 官方脚本),进度实时显示在卡片上;一种方式失败会自动降级到下一种,**全部方式都失败才报错**,并列出每种方式各自的失败原因;也可改用「在终端安装」手动兜底。同一时刻只跑一个后台安装 / 更新 / 卸载任务,任务进行中其它卡片的对应按钮会暂时禁用;不具备更新条件的 agent(非 npm/brew 安装)「更新」按钮直接不可用并说明原因
  - npm 方式遇到网络类失败会先自动换 npmmirror 镜像**重试一次**,再计入降级
  - 每种方式的单次尝试有 **10 分钟整体超时**:超时即按该方式失败处理,自动降级下一种方式,全部方式都失败才报安装失败;长时间无动静时,看任务卡片的输出尾部(保留最后 50 行)判断是慢还是卡住
  - 暂不支持卸载 script(官方脚本)装的 agent——请按官方文档手动卸载;npm/brew 装的支持卸载(带归属校验,不是该管理器装的不卸),且只移除程序本体,配置与历史数据保留;卸载失败时可用「在终端卸载」按 kaya 实际尝试的命令手动兜底
- **自定义命令名(改了名的 agent 也能识别)**:如果你把 agent 的 CLI 命令改了名(比如用 `myclaude` 替代 `claude`),在 agent 卡片的「命令名」一栏补上这些名字(逗号分隔,支持全角逗号);保存后安装检测、前台运行识别、启动命令一律同时认原名与自定义名。识别不到时不影响保存,等 PATH 里的命令就位后状态会自动转正。另外,agent 官方二进制的进程别名(如 kimi code 用 `kimi -r` 重启会话后进程名会变成 `kimi-code`)由 kaya 内置识别,无需手动添加
- **模型接入(「模型网关」卡)**:agent 详情页的「模型网关」卡负责模型接入——「经网关接入」开关 + 「默认模型」选择(可选项 = 该 agent 协议族可用的库模型,按供应商分组,不可选的带原因);新增 / 修改 / 删除供应商与模型都在**「设置 → 模型」**—— 模型只在那一处维护。**这座库与对话侧「我的模型」是同一座** —— 同一供应商带三个可选协议端点(对话 / Anthropic / OpenAI)与一份模型清单,不同 agent 各取所需,设置页里同样能看到并直接拿来聊天。接入后 agent 配置写成网关形态:接口地址恒指向本机回环网关,模型显示为友好名称(如「Deepseek (deepseek-flash)」),**真实接口地址与 API Key 不落 agent 配置文件**;关闭开关即撤除 kaya 的配置,按接管前快照恢复原受管键,原 provider/model 条目只补缺失、当前同名条目优先
  - **按协议接入**:Claude Code 使用 Anthropic 端点;Kimi Code / OpenCode 使用 Chat 兼容端点：优先选启用且非空、wire=chat/both 的 OpenAI 端点，仅在该切片不可用时回退「对话」端点;Codex 设置页的默认模型绑定要求可用 OpenAI 端点声明 Responses 或「两者」;接入后,在 Agent 内模型选择器可使用 Chat-only 供应商的 Responses→Chat 适配模型。是否可用以该 Agent 的目录与接入诊断为准,不兼容的模型会说明原因
  - **API Key 存系统钥匙串(macOS Keychain / Windows 凭据管理器)**(与对话侧模型共用同一个存储,库文件里**不存** key);对话里 kaya 改配置前会弹授权卡片,你确认后才落盘;密钥值不会回显在对话里;删除供应商会**一并删掉**该 Key(确认框里有提示)
  - **Codex 默认隔离与可选全局接管**:默认使用独立的 kaya profile,只影响从 kaya 启动或显式选择该 profile 的 Codex。开启详情页「全局接管」后,官方配置也会指向网关,会影响裸跑 Codex 与 ChatGPT 桌面版拉起的会话,开启前需二次确认。关闭、停网关、退出或崩溃后对账使用同一快照恢复流程;恢复失败会保留快照并提示,不会把失败当成恢复成功
  - **模型选择器**:接入后展示该 Agent 协议可用的库模型,按供应商分组并显示名称、上下文与能力信息。开启「只显示绑定模型」可收窄清单。库里新增/删除模型或修改能力后会同步;接管期间模型选择面由 kaya 管理
  - **模型库是唯一事实源与唯一写入点,一个供应商可同时服务多个 agent**:谁在用哪个供应商的哪个模型是明确记录下来的(不是靠配置值去猜),因此改 / 删供应商会直接作用到正在使用它的 agent。kaya 的 AI 助手也不能改 agent 配置文件里的模型身份键(模型名 / 接口地址 / 密钥)—— 这类修改一律被拒绝,并会引导到模型库
    - 改供应商(端点 / 模型清单 / API Key)后,已接入的 agent 配置**自动跟随**,不需要再操作;把 API Key 清空,网关里的对应密钥也一并失效
    - 删除供应商后,与它接入的 agent 会退出 kaya 的配置、回到它自己的默认行为 —— 不再继续使用被删的模型与密钥
    - **例外**:**kaya 没能认领这份配置**时(配置里没有 kaya 写过的标记 —— 例如从未接入过;或对应供应商在认领发生之前就已被删掉),那份 agent 配置文件里遗留的 kaya 设置**不会被自动清理** —— 对该 agent 重新接入一次即可收敛
    - 没接入的 Agent 不受影响。明确接入后,kaya 会备份并移除或隐藏接管时已存在的非 kaya 模型/provider 选择项;接管后新增的条目保留。撤除时合并恢复原条目,当前同名条目优先;其它配置字段仍按各 Agent 的受管键范围处理
    - 「在用」只统计真正经网关接入的 agent(接入开关关着的占位不计);如果 agent 的配置文件被别的工具改过,详情页会显示「配置在 kaya 之外被修改」徽标,点「重新接入」即可重新应用
    - 仅端点碰巧相同不会把手写配置计为「在用」;绑定与标记共同决定托管关系。明确接入前会捕获原值,无法证明能恢复的用户端点/模型值不会被本轮覆写,并显示提示;损坏的原快照保留,不会重新拍摄覆盖
    - 某个 agent 的配置文件损坏时只影响它自己:其余 agent 的配置照常更新,出错的那个会在下次操作时自动重试
    - **边界**:撤除按「kaya 第一次接管之前」的逐键快照还原;老版本(有快照机制之前)接管过的配置没有快照,撤除退化为只摘 kaya 写的键,接管前的旧值请手动恢复

**配置优化**

在 Agent 详情页的「配置优化」卡点**「优化配置」**,kaya 会读一次脱敏后的配置现状(可优化键的现值、绑定模型的库元数据、确定性初判问题),再让模型提出带出处的建议。分析是**只读**的,不写盘;建议和 kaya 的内置推荐会合并成**一张清单**:

- **AI 建议**逐条带出处(官方文档快照的真实文件 / 模型元数据字段 / 内置优化项的键),并经过 Rust 校验器 fail-closed 审核:未知 agent、拒写键、白名单外的键、你显式设置过的值被非「事实修正」级改动、虚报分级、编造文档路径、值域越界、空操作——都会被拦下,分成「可勾选 / 需手动处理 / 被安全闸拦下」三组**透明展示**,不静默丢弃。
- **内置推荐**是 kaya 自己的一组确定性优化(状态行 / 事件钩子 / 自动压缩等),只追加 kaya 自有条目,按组勾选。

勾选后点**「应用所选」**,两路各自下发、**互不吞错**:

- AI 项:一次性授权(绑定提案哈希 + 勾选子集哈希,用后即焚、重启即清)→ 深合并写入(带 `.bak` 备份)→ **逐键读回校验**,任一项不符自动从备份回滚,卡片给出 ✓ n/m 与失败明细。
- 内置项:`agents_tune_apply` 整体应用,组头常显「还原」;没有可撤项时置灰并说明原因。
- 两路各自 toast、各自在清单上留「未应用」痕迹;一路失败另一路照常执行。

**语义后验**:文件读回只能证明「写进去了」,不证明「生效了」。写入成功且映射到状态栏维度的键会进入「待生效确认」;agent 重启后解析到目标值即翻「已生效」。超时翻「未确认」——**不自动回滚**,由你判断。

**撤销**:撤销会核对本次写后的文件哈希;如果你之后又编辑过,会保留你的修改并拒绝覆盖。AI 撤销记录只在当前应用进程内有效;内置推荐的「还原」独立保留。同一配置文件上的 apply 与 rollback 按路径串行,不会互相覆盖。Windows 上脚本类推荐暂不支持;Kimi Code 的状态栏使用官方默认。

模型名、端点、密钥、思考档位默认值仍只在「设置 → 模型」维护,不能借配置优化绕过——codex 的 `model_reasoning_effort`、claude 的 supported capabilities 与 effort level 都在拒写清单里,它们由模型库统一投影。

- 通过 IM 渠道(飞书 / Slack / 企微)远程使用时:仅支持读/改配置(同样有授权卡);安装、更新与管理中心的状态查询在 IM 里不可用(运行中 agent 的实时状态可只读查询)

## 让 AI 读取文件

默认 AI 不能读取你电脑上的文件。如果你想让 AI 帮你分析一段代码、查看一个日志、解释一个配置文件,需要先把文件放进可信目录。

**步骤**

1. 在终端里创建或使用 `~/.kaya/` 目录:

```bash
mkdir -p ~/.kaya/my-project
cp ~/my-project/main.ts ~/.kaya/my-project/
```

2. 在对话里告诉 AI 文件路径:

```
读取 ~/.kaya/my-project/main.ts 并解释它做了什么
```

3. AI 会调用允许的读取命令(如 `cat` 或 `head`)读取文件内容,展示给你

4. 用完后删除不再需要的副本:

```bash
rm -rf ~/.kaya/my-project
```

**允许的读取命令**

在 `~/.kaya/` 下,以下命令可用:

- `cat` / `bat`:读取文件内容
- `head` / `tail`:读取文件开头或结尾部分
- `grep` / `egrep` / `fgrep` / `rg` / `ag` / `ack` / `sed -n`:在文件内容中搜索
- `sort` / `uniq` / `tr` / `cut` / `nl`:文本整理与变换
- `strings` / `xxd` / `hexdump` / `od` / `base64` / `base32`:查看二进制或编码内容

Windows 上还有 PowerShell 的等价物 `Select-String`(`sls`)与 `findstr`,路径同样必须在 `~/.kaya/` 下。

`wc`、文件哈希等命令即使只返回计数或摘要,带文件路径时仍受 trusted-read 约束,不能借此查询 `~/.kaya/` 之外的文件内容或大小。

**不允许的操作**

即使在 `~/.kaya/` 下,以下操作仍然被拦截:

- 修改或移动已有文件(`sed -i`、`mv` 等)
- 删除文件
- 执行文件内容

唯一的写入例外:把命令输出重定向写入 `~/.kaya/` 下的文件(如 `echo hello > ~/.kaya/note.txt`)是允许的,但目标必须带安全的文件扩展名——无扩展名或 `.sh` / `.exe` 等危险后缀仍被拦截。除此之外 AI **只能读,不能改**已有文件。这是设计如此。

**下载文件**

AI 也能从网络下载文件到 `~/.kaya/`(例如 `curl -o ~/.kaya/...`)。危险的文件类型(如 `.sh`、`.exe`、`.dmg`)会被拦截。

**提醒**

- 不要因为有脱敏就主动把密钥放进 `~/.kaya/` 给 AI "看看"
- 用完后及时删除 `~/.kaya/` 下不再需要的文件
- 不要在可信目录中放入指向外部敏感文件的符号链接;部分路径检查采用词法规则,不保证解析全部符号链接,已知边界见隐私文档 §5.1

## 使用联网搜索

kaya 支持通过 Tavily 让 AI 联网搜索最新信息。Tavily 是可选功能,默认关闭。

**启用步骤**

1. 打开 [tavily.com](https://tavily.com) 注册并获取 API Key
2. 在 kaya 里打开 **⚙ 设置** → **通用** 标签页的 **联网搜索** 小节
3. 填入 Tavily API Key
4. 点击保存

**使用**

启用后,在对话里让 AI 搜索:

```
搜索一下 React 19 的最新特性
查一下 DeepSeek 最新模型的消息
搜索并总结这篇英文文章的主要内容
```

AI 会调用搜索工具获取结果,整理后告诉你。

**隐私说明**

Tavily 是一条**可选的额外联网搜索出站路径**:启用后,它会把你的(经脱敏后的)问题文本发给 Tavily。Tavily 收到的只是你问 AI 的问题文本,不是你的文件、不是你的 API Key。**关闭 Tavily 即可关闭这条外发路径**。

**可信度提醒**

搜索结果是来自互联网的**不可信输入**——可能是过时、错误或带有偏见的内容。AI 给出的总结仍然需要你核实关键事实。开启 Tavily 不会让 AI 跳过内容保护,搜索得到的网页内容在进入模型上下文前也会经过脱敏。

## 通过飞书 / Slack / 企业微信使用 kaya

v2.1.0 起,kaya 支持把 IM 消息接到本机:在飞书、Slack 或企业微信里给机器人发消息,由本机 kaya 的 LLM 处理并**流式回复**——不用打开 kaya 窗口,在 IM 里就能用。

**开启路径**

1. 打开 **⚙ 设置** → **IM 渠道** 标签页(也可从系统菜单 kaya → **IM 渠道…** 直达),选择平台——当前版本开放**飞书**与 **Slack** 接入,**企业微信入口置灰「(即将支持)」**(存量企微配置保留,后续版本再开放)
2. 飞书:**推荐点「飞书扫码接入」**(仅飞书平台提供):用手机飞书扫描二维码并确认,kaya 自动创建应用并回填 App ID 与创建者 open_id 到 allowlist;App Secret 直接写入 **系统钥匙串(macOS Keychain / Windows 凭据管理器)**,不落盘、不回读显示
   - 手动配置(fallback):自行到[飞书开放平台](https://open.feishu.cn)或企微管理后台创建应用后,填入飞书 App ID + App Secret,或企微 BotID + Secret
3. Slack(**仅手动配置,无扫码**):到 [api.slack.com/apps](https://api.slack.com/apps) 创建 app → 开启 **Socket Mode** 并生成 App-Level Token(`xapp-` 开头,scope `connections:write`)→ OAuth scopes 添加 `chat:write` → Event Subscriptions 订阅 `message.channels` / `message.groups` / `message.im` / `message.mpim` → 安装到 workspace 拿到 Bot Token(`xoxb-` 开头)→ 回到 Settings → IM 渠道填入这两个 token(双 token 均直接写入系统钥匙串)+ member ID allowlist
4. 配置**准入 Allowlist**:每行一个用户 ID(飞书填 open_id「ou_」开头,Slack 填 Member ID「U」开头,可在对方个人资料页复制;企业微信填成员 userid);飞书扫码接入会自动锁定创建者本人
5. 点击**启动渠道**,状态显示「● 运行中」即可在 IM 里发消息。**如提示无权限**,请到对应平台后台为应用开通所需权限(飞书 im:message 相关权限并发布版本;Slack 核对 scope 与事件订阅)

**要点**

- **长连接直连平台**:飞书走官方 WebSocket 长连接,企微走官方 openws 通道,Slack 走 Socket Mode WSS,**不需要公网 IP 或回调服务器**
- **allowlist 默认拒绝陌生人**:名单外的用户消息直接丢弃,不进 LLM;名单为空时渠道无法启动
- **同一套隐私防线**:IM 消息与桌面 chat 走同一条五道关卡 pipeline(输入脱敏 → 命令白名单 → 安全检查 → 隔离执行 → 输出脱敏);IM turn 的工具表与桌面基本对齐(可读终端 / 任务清单 / 记忆检索),仅有三个刻意例外——定时任务管理、跨 agent 任务队列与「AI 创建任务」不开放给 IM;IM 侧可在对话里直接说「记住:……」记信息(按意图门控注册记忆写入工具,写入由证据自动裁决直接生效并按真实结局回报 —— 归档时明说未生效),记忆检索输出同样过脱敏;`terminal_write` 仍由 coding 模式总闸照管——总闸为桌面与渠道共享的原子标志,运行中在桌面扳动开关即时写入渠道侧,下一 IM turn 生效
- **桌面 → IM 镜像(opt-in,默认关)**:开启后桌面 chat 的消息流实时推送到你指定的 IM 聊天,你的输入以「你:…」前缀文本回显;IM 侧回复也同步出现在桌面聊天面板。新建桌面会话时镜像自动迁移并推一条「已开启新会话」通知。开关入口有两处——Settings 的「镜像桌面聊天到飞书」checkbox 与顶栏 coding 旁的镜像 icon,是同一个开关,点击即时生效
- **飞书 / Slack 授权卡片**:IM turn 触发 terminal_write / agent 配置修改授权时,飞书 / Slack 里直接收到带「批准 / 拒绝」按钮的卡片(Slack 为 Block Kit 交互按钮),决议与桌面授权卡共享同一份授权状态(互认);操作者必须在准入 allowlist 内。批准后 kaya 会**自动补一个回合**,请 AI 重试刚才被暂停的操作——不用再手动发一句话把它唤醒
- **agent 状态主动通知**:镜像开启时,编程 agent 等输入 / 跑完空闲 / 上线 / 退出会主动推送到镜像聊天(按渠道语言出中文 / 英文,同类事件有冷却不刷屏);kaya 自动回合(时机询问 / 状态汇报等)在 IM 侧只回显一句话摘要而不是指令全文,且同一事件的「主动通知」与「回合镜像」只发一份,不再重复刷屏
- 会话映射与对话上下文落 `~/.kaya/`;**IM 收发行暂未接入审计 JSONL**。LLM 用顶栏模型切换器里选的模型
- **如实说明(企微限制)**:企业微信的镜像回显与主动通知依赖活跃回调,纯桌面场景(无 IM 对话在途)可能静默丢失;本轮仅飞书做了真机验证,Slack 尚未经真机 workspace 验证

隐私细节详见 [docs/PRIVACY.md](./PRIVACY.md) 的「IM channel 入口」与「IM 渠道与镜像」两节。

## 远程访问(云中继)

v2.3.2 起,kaya 支持从**浏览器**远程查看和操作这台设备上的 kaya:对话、运行中的 agent 状态、授权审批都与桌面实时同步——不在电脑前也能继续推进任务。

**开启路径**

1. 打开 **⚙ 设置** → **远程访问** 标签页
2. 确认已登录 yunhou 账号且有有效订阅(未登录 / 无订阅时开关禁用并给出引导)
3. 打开「启用远程访问」开关;状态显示「● 运行中」且连接状态为「已连接」即就绪
4. 在浏览器登录 yunhou 官网并打开「远程控制」页,即可访问此设备

**要点**

- **opt-in,默认关**:不启用就不存在任何远程通路;关闭开关即断连
- **中转仅内存透传**:对话内容经 yunhou 服务器中转,服务器只转发、不落盘;远程端与桌面看到的内容一致。**API 密钥不经中转**,仍由本机直连 provider;全程 TLS 加密
- **同一套隐私防线**:远程回合与桌面 chat 走同一条五道关卡 pipeline(输入脱敏 → 命令白名单 → 安全检查 → 隔离执行 → 输出脱敏);`terminal_write` 等写操作仍走同一授权存储,远程端审批与桌面授权卡互认
- **设备身份**:启用后自动生成本机设备 ID(可复制);设备名可自定义(≤64 字符),便于多台设备区分
- **状态自查**:面板实时显示运行状态、连接状态(连接中 / 已连接 / 离线自动重连 / 鉴权失败)、最近错误与最近活动时间;付费状态失效会自动停止并在状态区标明
- 设备身份信息落 `~/.kaya/remote/device.json`(0o600 权限),会话映射与对话上下文留本机;**远程收发行暂未接入审计 JSONL**

隐私细节详见 [docs/PRIVACY.md](./PRIVACY.md) 的「远程访问(relay 中转)」一节。

## 跨机协同(设备与设备)

同一账号下的两台 Mac / PC 可以**互相派活**:在 A 机的聊天 / ToDoList 里把任务派发给 B 机上正在运行的编程 agent,B 机 agent 的状态、证据与授权请求实时回传;B 机上的运行实例以**设备名徽标**出现在侧栏与 `@` 菜单里。点击远程卡片会选择该 Agent 并绑定 Chat,本机终端 tab 保持不变。

**开启路径**

1. 两台设备登录同一 yunhou 账号(跨机协同复用远程访问的 relay 连接,各机需有有效订阅)
2. 在**执行端**(要接收任务的那台)打开 **⚙ 设置** → **跨机协同**,打开总开关,把发起端设备加入**白名单**(可再按 agent 圈定范围)
3. 发起端在 ToDoList 的任务上选择远程目标(设备 + agent)即可派发;派发文本要过执行端的授权卡

**要点**

- **执行端准入 fail-closed,默认关**:总开关默认关闭 + 逐设备白名单;未准入设备的执行向请求一律拒收。白名单落 `~/.kaya/remote/peers.json`(0o600,损坏按默认关)。**发现与状态帧不受该执行准入闸控制**:远程访问启用后,同账号设备即可交换设备发现和 Agent 状态摘要;关闭协同或不加执行白名单不等于设备不可见
- **授权双端可批,权威在执行端**:写入对端终端前需要授权,授权卡两端同时显示(分别标注「来自设备」/「目标设备」),任一端批准即生效,可记住「该设备免再问」。派发文本按编程 agent 的输入行提交,控制字符会被拒收
- **按需查看输出**:执行端允许「对话中转」且双方版本支持时,可按需读取远程画面或报告,无需调用对端模型。读取前后重新检查准入范围和实例,内容经脱敏且最多 8 KiB;切换实例后清除旧输出
- **回答当前菜单**:支持的远端待决菜单可在侧栏或工作台选择 1–9,也会进入 Chat 待决卡,可在输入框输入数字回答。回答绑定当前实例和本次菜单,每张票只用一次;本机回答或已授权 LLM 写入后旧票撤销,相同等待未结束不会重签。已过期、已回答或目标换代时拒绝写入,超时显示结果未确认且不自动重发。退出或离线会收尾待决卡。旧端显示升级提示;此入口不提供任意按键或运行时配置修改
- **远程状态快照与页面恢复**:页面重载会按设备恢复连接基线,即使该设备当前没有 Agent,也能接入随后出现的实例;短暂断线通过本轮握手恢复,退休连接和迟到事件不会重开旧状态。恢复快照与实时事件按同一水位衔接,退出、离线或实例换代不会被旧快照覆盖;显示投影仅保存在本机内存并有界
- **relay 仍是哑管道**:设备间帧经同一条 relay 连接中转,不解析、不落盘 payload;帧内容离机前过输出脱敏
- **断线语义**:对端离线时条目显示「重连中」,重连后自动对账(仍在跑 / 已退出 / 授权待决);对账确认仍在跑的条目不会重复派发;对端任务记录已丢失时如实归因,可手动重试或标记完成
- **依赖服务端支持**:跨机协同需要 yunhou relay 服务端的设备路由与发送方身份盖章;服务端升级前两台设备互相不可见,功能不可用(客户端开启后也不会产生设备间通路)

**在聊天里询问或转达**

接收端还需在该设备的准入项里允许「对话中转」(默认关闭)。发起端在聊天里 @ 远程 Agent,消息先交给对端 kaya:它可以查询圈定范围内的 Agent 状态、报告与终端屏尾,也可以通过授权把指令转达给目标。转达缺少授权时,两端显示已有授权卡,批准前明确显示等待授权;审批及实际写入时重新检查准入与所绑定的实例,Agent 重启后旧请求不会转发给新实例,需要重新绑定。此模式不开放 shell、文件修改、记忆写入或联网搜索工具;Agent 读权限在工具执行时按当前运行实例重新检查,不注入全机 Agent/任务态势。全局已审批规则与核心记忆仍遵循对端本机会话的上下文契约。

两端都显示带设备来源的对话;发起端接收本次最终回复,不逐字转播对端思考与工具输出。离线、拒绝或超时会显示终态。ToDoList 的任务派发仍走独立的任务/授权流程。

隐私细节详见 [docs/PRIVACY.md](./PRIVACY.md) 的「跨机设备协同」一节。

## 使用思考模式

**什么是思考模式**

开启后,AI 在给出最终回答前,会先进行一段**链式推理(Chain-of-Thought)**:把它的思考过程以可折叠的段落展示给你,然后再回答你的问题。

**为什么使用**

- **可解释**:你能看到 AI 为什么得出这个结论
- **可审计**:推理过程会单独记录,事后可回放
- **更准确**:对于复杂问题,带推理的回答通常比直接回答更准确

**代价**

- **更慢**:AI 需要时间思考再回答
- **更贵**:消耗的 token 更多,API 费用更高
- **可能更长**:推理内容会占一定篇幅

**怎么开启**

思考能力现在是**按供应商 / 按模型**声明的,没有单一的全局开关:

1. **对话端点的思考开关** —— 设置 → 模型 → 供应商详情,在对话端点旁勾选「思考模式」。决定这条端点是否透传推理参数;kaya 会按端点协议与当前模型 ID 自动适配(DeepSeek 注入 `reasoning_effort` + `thinking`,OpenAI o 系列透传 `reasoning_effort`,OpenRouter 注入 `reasoning: { effort: "high" }`,GLM / Qwen 注入各自的开关,Ollama / Custom 端点上的 DeepSeek 推理模型也注入 `reasoning_effort` + `thinking`;其余模型不注入)。
2. **模型行的思考声明** —— 如果目录数据不准,或者你要关掉一个目录说支持的模型,在模型行的「思考(Thinking)」复选框上勾选 / 取消。这是**三态**:自动(走目录兜底)/ 支持 / 不支持,**显式声明压过目录结论**。点「清除声明」会同时摘掉思考与档位声明,回到自动判断。
3. **思考档位** —— 模型支持思考时,行上会出现「档位」chip 组(**minimal / low / medium / high / xhigh / max**)与「默认档」下拉;默认是「按目录自动判断」,点任一颗就把当前生效集合固化成显式声明,清空则回到自动。这些档位会投影到四家 agent 的原生键,所以 agent 状态栏里的 `thinking: <level>` 与实际行为一致。

**注意两种「思考」不是一回事**:聊天请求是否带推理参数由**对话端点开关 + 当前模型 ID** 决定;模型行的思考三态 / 档位服务于编程 agent 配置投影、目录徽标与配置优化分析,不会变成聊天请求里的思考布尔值。改了声明后,运行中的 agent 要等下一次同步(下一次保存 / 重新接入 / agent 重启)才会看到新值。

**切换推理模型**

供应商详情页已没有 **Reasoning Model** 编辑入口。存量 `reasoning_model` 数据仅由审计评估的 **AI judge** 消费(用它选择评判模型),聊天请求不使用它,也不会用它切换实际请求的模型 ID。

要切换 AI 使用的模型,请改「设置 → 模型」里当前选中的模型。推理参数由端点协议与当前模型 ID 自动适配,不需要单独切换一个「推理专用模型」。

## 管理会话与历史

**会话持久化**

kaya 自动保存你的对话。三个层级自动同步:

- UI 消息(左侧对话窗口)保存在应用本地
- LLM 上下文(供 AI 回顾)保存在 `~/.kaya/conversations/`
- 审计日志(详细事件流)保存在 `~/.kaya/audit/`

刷新应用或重启电脑后,对话和设置都会自动恢复。

**新对话**

点击右上角 **↻ 新对话** 按钮:

1. 停止当前正在进行的回合(如果有)
2. 清空当前 UI 消息
3. 生成新的会话上下文
4. 开始一个全新的对话

**查看历史会话**

**新对话** 是一个纯图标按钮,旁边没有历史列表。查看历史的入口有两个:在对话输入框用 **`/sessions`** 命令列出历史会话并点卡片查看(**只读**,不能恢复上下文继续聊);或打开 **⚙ 设置 → 审计** 查看完整事件流。

**压缩上下文(/compact)**

会话变长后,在对话里输入 **`/compact`** 可以把当前会话的上下文压缩成一份摘要,之后对话基于摘要继续(你看到的聊天记录保留不变)。压缩前 kaya 会先自动提炼一次记忆——完整历史里的重要信息先进记忆库,不会因压缩丢失。压缩过程在消息流里有进度提示(提炼记忆 → 生成摘要 → 完成)。该命令需要登录;使用内置模型压缩需要订阅。

**清除数据**

kaya 没有逐会话删除的 UI。要清除所有本地数据,在终端运行:

```bash
rm -rf ~/.kaya/
```

这会一并删除会话上下文、审计日志、记忆库、Token 用量统计、网关配置与隐私保护明细(它们都在这个目录下)。**界面上的消息与设置不在 `~/.kaya/`**,而是存在应用本地存储里;想连界面消息一起清掉,需要清除应用的本地数据(或在应用内开新对话覆盖)。

**会话标签页、退出行为**

- 关闭标签页(**⌘W**):弹出确认对话框;确认后,关闭该标签页,合并该标签页的 shell 历史到 `~/.zsh_history`
- 关闭整个 kaya(红 X):弹出确认对话框;确认后,合并所有活跃标签页的 shell 历史到 `~/.zsh_history`,然后退出
- **⌘Q**:不弹确认对话框;kaya 先尝试合并本地历史到 `~/.zsh_history`,然后退出。如非必要,请优先使用红 X 退出

## 记忆机制(Memory)

kaya 能**跨会话记住**你的偏好、重要决定和项目约束——换一个新对话,它依然记得。

- **记什么、怎么记**:对话中有价值的信息会被提炼成「记忆候选」,由 Agent **按证据自动裁决** —— 事实可凭用户指令 / 陈述与重复模式写入;规则只有在你的原话带显式规则意图、且待记正文与候选精确对应时才成为恒在场约束,真实消息 id 或模型自报证据本身都不算充分证明。助手单方面推断的内容不进活跃记忆(最多冷存归档);规则容量满时新规则归档,而不是挤掉你已有的规则。**没有待审队列**,写入立即生效;你可以在 设置 → 记忆 里事后查看、编辑、回滚或彻底删除
- **直接告诉它「记住」**:在对话里明确说「记住:……」「别忘记……」「把 X 记住」这类说法即可记下;指令不一定在句首——「先跑测试。记住:周五发版」「这点记住」「周五发版,记住」这类中段 / 句尾形态同样能识别。整条消息就是记住指令时,kaya 在本地直接记住(不消耗 LLM 配额、不需要登录);指令混在其它内容里(「记住 X,然后做 Y」或上述中段形态)则由 AI 在当次对话中提炼写入。记住的内容若含密钥等敏感信息,会先脱敏再入库
- **三层记忆:核心 / 语义 / 情景**:置顶到「核心」的记忆会随每次对话带给 AI(最多 24 条);其余情景记忆由 AI 按需检索,不占用每轮上下文;当同类主题的情景记忆反复出现时,巩固会自动把它们归纳出一条「语义记忆」(例如从多条「agents.md 需要精简」归纳为一条长期结论)——归纳结果直接生效。语义记忆不随时间衰减,被归纳的原始条目保留,可随时查看它由哪些成员归纳而来;不常用的情景记忆会随时间自然衰减、归档,再次被用到的记忆会被强化
- **规则与事实、全局与项目**:记忆分两类——**规则**是「每回合都要在场」的行为约束(如「提交前先跑测试」),只有你的原话带显式规则记忆指令、且剥离后的待记正文与候选精确匹配时才自动生效,此后每次对话都带给 AI,不经检索(全局最多 16 条、每个项目最多 8 条);**事实**是按需检索的背景信息。每条记忆还可绑定**项目作用域**:说「记住:本项目:……」、或在 设置 → 记忆 里把条目改为「本项目」,它就只在对应目录下的会话里生效(项目规则注入时带「(本项目)」标记)。AI 每回合还会看到一份**记忆索引**(一行一条的摘要)——它知道自己有什么记忆可查,需要细节时再调取,索引只占极少量上下文
- **推断内容不会静默生效**:助手单方面推断的候选不会进入活跃记忆 —— 达到长期价值门槛(或本身是规则形态)时冷存为「已归档」,在 设置 → 记忆 打开「显示已归档」即可看到、可一键恢复;低于门槛、内容为空或整条只剩敏感信息占位时**拒收、不入库**。自动生命周期只做新增 / 强化 / 归纳 / 归档 / 可撤销的取代,**从不自动物理删除**
- **最近自动变更**:设置 → 记忆 有「最近自动变更」折叠区,可回看最近的新增 / 强化 / 取代 / 归纳 / 归档记录;记忆时间线按时间倒序展示
- **何时提炼**:新对话收尾时自动提炼上一会话;应用启动时和运行期间也会定期自动提炼(默认开,可在 设置 → 记忆 关闭);也可以在 设置 → 记忆 里手动点「立即巩固」。使用内置模型提炼需要订阅;自带模型(BYOK)用你自己的配置;Ollama 本地模型则完全不外发。记忆从功能启用时刻开始记录,不追溯启用前的旧会话
- **删除即遗忘**:全部记忆只存在本机 `~/.kaya/memory/`。「丢弃」是逻辑删除(留痕可审计);条目操作区的「彻底删除」会把内容与全部历史版本一并抹除,不可恢复
- **检索摘要会标出证据与冲突**:AI 检索到的每条摘要都带证据来源(用户明确 / 用户陈述 / 重复模式 / 助手推断 / 语义归纳),未决冲突会带对方的条目 id —— 新旧说法冲突但不足以合法取代时**两条都保留**,由 AI 在上下文里判断;仅凭文本相似度绝不会自动覆盖旧记忆

## 定时任务(Schedules)

让 kaya 按时间表自动发起对话回合——例如每天早上让它检查各 agent 的进展,或每隔一段时间总结一次终端里的变化。

- **创建与管理**:打开 **⚙ 设置 → 定时任务**,填写要做的事(prompt)并选择节奏——**间隔**(每 N 分钟)或**每天**(本地时间 HH:mm);可设**次数上限**(留空不限;跑满自动停用,重新启用即重新计数)。任务可启停、可删除;暂不支持编辑,要改就删了重建
- **到点自动跑**:到时间后 kaya 自动以该 prompt 发起一个对话回合,过程与结果照常出现在消息流和审计记录里;对话正忙时会顺延重试,不会静默丢失当天任务
- **同一套权限门**:定时回合与普通提问走同一套门禁——需要登录,使用内置模型时需要有效订阅;不满足时该周期静默跳过,不弹窗打扰
- **只存在本机**:任务清单随应用重启保留;每天任务在当天过点后才会触发(新建时当天已过点的,从明天起生效)

## 查看审计记录

kaya 会为**已接入审计的来源**(如桌面聊天与定时回合)自动记录审计日志,你可以随时回看这些会话里 AI 做了什么;IM / 远程收发行暂未接入审计 JSONL。

**打开审计页面**

**⚙ 设置** → **审计**。

**会话列表**

左侧列出所有会话,按时间排序。点击任一会话查看其事件流。

**事件类型**

- 会话开始
- 你的每次输入(含脱敏结果)
- AI 每次工具调用决策(为什么允许或拒绝)
- 工具调用完成(含 stdout、stderr、退出码)
- AI 的每次推理片段
- 配置优化的六个节点:提案 / 授权 / 已应用 / 自动回滚 / 用户撤销 / 应用失败(只记 agent、提案号、条目数与**键名**,不记值)
- 网关脱敏事件(`gateway-scrub`):只记类别计数、字节数与实际路由,**零内容**
- 错误事件

**运行评估(Evaluate)**

点击会话右侧的 **Evaluate** 按钮,kaya 会做三轮复审:

1. **规则回放**:用当前版本的策略,重放所有工具调用决策。任何与当前规则不一致的地方都会被标记
2. **异常启发式**:检查 5 类异常模式 —— "文件读取未脱敏"、"网络输出未脱敏"、"环境变量输出未脱敏"、"工具调用前缺少推理片段"、"Tavily 大输出未脱敏"
3. **AI 评判**:由独立 AI(始终带思考模式)对整个会话做最终复审

**审计日志 vs App 日志 vs 隐私明细**

- **审计日志**:已接入审计来源的会话所涉及的 LLM 事件,用于事后回放;**含脱敏后的正文**(你的输入、工具输出前 2,000 字符、模型回答与推理片段)与决策元数据。真正**零内容**的只有网关脱敏事件 `gateway-scrub`
- **App 日志**:跨会话的应用诊断日志,用于排查 kaya 本身的运行问题(含裁剪 / 漂移 / 网关上游超时等 warn)
- **隐私保护明细**:网关逐命中的令牌化 / 告警 / 还原记录,**唯一会存网关命中原文的本地存储**,在「设置 → 网关 → 隐私保护统计」里看

三者独立,不要混淆。

## 设置参考

打开 **⚙ 设置**:宽窗口下左侧是按组排列的导航——**编程**(模型 / 编程 Agent / 网关)、**通用**(通用 / 记忆 / 快捷键 / 定时任务)、**连接**(IM 渠道 / 远程访问 / 跨机协同)、**系统**(账户 / 审计 / 日志与调试);窗口较窄时降级为顶部横排标签页。默认打开**模型**标签页。**联网搜索、Shell、语言、脱敏** 等都是 **通用** 标签页内的小节,不是独立标签页;**模型** 标签页是模型库(见下);**日志与调试** 是原 App 日志与调试(dev 构建)合并而来。

**IM 渠道**

把飞书 / Slack / 企业微信消息接到本机 kaya:配置平台凭据(存系统钥匙串(macOS Keychain / Windows 凭据管理器))、准入 allowlist,启动 / 停止渠道并查看运行状态。详见 [通过飞书 / Slack / 企业微信使用 kaya](#通过飞书--slack--企业微信使用-kaya)。

**编程 Agent**

编程 agent 的安装 / 更新 / 卸载、自定义命令名与模型绑定都在这个标签页(即原独立的 Agents 管理中心,现已并入设置)。详见上文「Agents 管理中心」。

**模型(设置 → 模型 标签页)**

模型库的完整说明见上文**「模型库与供应商」**。这里只列设置层面的位置:

- **左栏供应商 / 右栏详情**:「+ 添加供应商」从 200+ 家目录选择或自定义;详情页管认证方式、三协议端点、模型清单与每一行的元数据。
- **决策层**(同 tab 上方的全局开关):**快速决策层**(简单问题走瘦身回合、终端事件先过语义过滤)与**指令确认模式**(每次询问 / 自动派发排队任务)。两者立即生效、无需保存,且都不影响终端写入的授权卡。
- **用量统计**:tab 顶部可切到「模型库 | 用量统计」两段。

**用量统计**

「设置 → 模型 → 用量统计」可看最近 90 天(默认窗口)的 Token / 请求总量、按模型与按 Agent 的合计,并以天 / 周 / 月分桶、按 Agent 过滤、手动刷新。聊天与模型网关**共用同一套记账**,只记供应商 / 模型 / Agent 标识与实际计数,不记请求正文;上游没返回 usage 时不编造。

- 独立于 agent loop 的辅助调用(快速决策、任务提炼、记忆巩固)不计入;入口路由判定本身不计,但它触发的瘦身回合属于主聊天回合,照常计入 —— 所以数值可能低于供应商账单。
- 事件只在本机保留 180 天。**该统计不等同供应商账单或余额。**
- 云端上传的范围、同意与关闭行为见下方「账户」及[隐私设计文档](PRIVACY.md)。

| 项 | 说明 |
|---|---|
| 供应商 | LLM 服务商:从 200+ 家目录选择,或自定义 OpenAI 兼容端点;同一服务商可建多条账号 |
| 认证 | API Key 或 OAuth 登录;凭据只进系统钥匙串,库文件**不存** key |
| 端点 | 每个供应商可同时启用 **对话 / Anthropic / OpenAI** 三种端点;模型按协议族归属 |
| 模型清单 | 目录预填 + 手工增补;支持在线刷新;同供应商多模型共用一份凭据 |
| 模型元数据 | 上下文窗口、输出上限、图片输入(自动 / 支持 / 不支持)、思考(自动 / 支持 / 不支持)、思考档位与默认档、视频 / 音频输入 |
| 存量 `reasoning_model` 数据 | 仅审计评估的 AI judge 消费;详情页无编辑入口,聊天请求不使用(详见「使用思考模式」) |

> 注:**最大上下文消息数** 控制 agent loop 保留多少条历史(保留 system prompt + 最近 N 条);持久化上限是 200 条 / 会话。

**网关(设置 → 网关)**

机制与边界见上文**「模型网关」**专章;这里是面板上有什么:

- **启用开关 + 状态行**:运行中 · 端口 / 已停止 / 被另一个实例占用(dev 与 prod 网关互斥;被占用时写操作会被拒绝并说明)。
- **脱敏档位**:网关独立档位,默认 strict(只自动拦截明确 secret,PII 不自动改写),可选 balanced / aggressive。用户输入始终 aggressive;工具输出默认 aggressive,可在「通用」里调整。
- **Claude 不由 kaya 托管**:打开后 kaya 不为 Claude Code 写任何托管配置(已写的会撤除),它的流量也就不经网关、不脱敏。
- **拒绝未知路径**:默认透传未识别的 API 路径并记告警;开启后直接拒绝(可能打断 agent 的辅助请求,所以默认关)。
- **命中计数**:已脱敏请求 / 告警事件 / 未知路径三项。
- **模型目录(只读)**:库 × 网关快照合并,展示三协议切片、Responses→Chat 适配、凭据就绪、视觉 / 思考徽标、上下文与「不可用原因」。第三方工具把本机网关当作供应商接入时,**模型名必须填下列 `kaya/<别名>` 之一**,裸上游模型名会被 400 拒绝;编辑模型请去「模型」tab。
- **用户令牌表**:固定替换规则 —— 出站把「真值」换成「令牌」,响应原样还原(例如 `张伟` → `person-a`)。

**隐私保护统计**(同一页顶部的子 Tab)

显示分类、动作、响应还原次数与逐条明细:默认展示全部规则记录,未替换的风险记录优先,再按规则置信度排序,已替换记录最后;「已替换 / 未替换」分别说明出站动作,响应还原只统计实际记录到的事件,未替换不直接宣称已泄露。可按类别、动作、Agent、模型路由、规则类型与时间窗筛选,按原文或令牌搜索,并把同内容命中聚合成出现次数、首次 / 最近出现。**明细包含命中原文与替换后的令牌**,仅存本机,默认遮罩、点击行才展开,不自动进入 LLM 上下文或诊断导出;展开区可核对原始时间戳、记录 ID / 请求 ID 并打开原始 JSONL。逐条请求审计默认折叠,只用于排查。界面读取最近 90 天、最多 5,000 条有效记录;可经二次确认「清空当前视图」或「清空全部记录」。它是独立的本地敏感数据存储,与不含内容的网关脱敏事件 `gateway-scrub` 不同(聊天审计日志则存脱敏后的正文)。

**网络代理(设置 → 通用)**

可为 kaya 自身配置手动 **HTTP / HTTPS / SOCKS5** 代理,主机填 hostname 或 IP,端口 1–65535,可选用户名与密码;SOCKS5 使用远端 DNS。密码采用 write-only 保存,只进入系统钥匙串,不留 localStorage;留空表示保留旧密码,也可显式清除。直连例外支持 hostname / IP / CIDR,保存时拒绝 URL、端口、路径、通配符及非法网段；`localhost` / `127.0.0.1` / `::1` 恒直连且不可移除。旧版本遗留的无法识别条目会在加载时逐条忽略并回到代理路径,设置页仅提示被忽略条数；加载不改写盘上配置,下一次显式保存按当前列表整写。

默认使用单个代理端点。开启「按目标协议分别配置」后,可同时保存 HTTP、HTTPS、SOCKS5 三个独立端点(各自启用与认证):每类目标优先使用专用端点;专用端点未启用时先回退 SOCKS5,最后才借用另一类端点(HTTP 经 CONNECT 可承载 HTTPS,HTTPS 代理也可转发 HTTP)。启用代理时至少需要一个端点,否则拒绝保存与启动。

**代理应用范围**:模型(Chat、供应商 OAuth)、网关上游、账号与登录、用量上报(Token 用量、心跳及所需令牌刷新)、联网搜索、IM 渠道、远程访问、更新八类出口可分别选择走代理或显式直连。直连范围不读取系统代理、PAC 或进程环境变量;未显式直连的范围在代理不可用时仍 fail closed。各业务自己发起的令牌刷新跟随该业务范围。

启用后,除显式设为直连的范围外,内置 Chat / BYOK / OpenAI Responses、模型网关远端上游、OAuth、模型目录与探活、Tavily、usage 上报、官网检查更新与 updater 下载、飞书 / Slack / 企微 / Remote 的 REST 与 WSS 都走当前代理配置选出的端点;审计 judge 也走同一出口。关闭代理时保留草稿并显式直连,不读取系统代理、PAC 或进程代理环境变量。代理不可用或凭据状态不确定时,未显式直连的请求 fail closed,不自动回退直连。

**Shell 隔离**:该设置只影响 kaya 应用自身的出站请求,不写 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`,不改 shell profile、不注入 PTY 启动参数。Terminal、PTY、AI 的 `run_shell` 子进程以及你从中启动的 Agent 完全不受影响;终端里的程序如需代理仍由你自行配置。

「云端 Token 用量」卡默认关闭;确认 `kaya-usage-upload-v2` 的上传清单后才开启。它只上传按 UTC 小时或天聚合的用量桶(source、agent、归一化 provider 键、模型 id、token 计数、请求次数),以及设备注册四字段(随机设备 id、OS 家族、kaya 版本、consent 版本),不上传对话或工具内容;关闭只停止本机后续上传,不删除已上传的云端数据。旧 schema 的上传状态无法证明历史身份时会停止上传并清除旧同意;重新确认后**默认只上传新用量**,最近 30 天历史需在预览明确范围后另行确认,当前桶无需等整点。关闭上传后**当前可信同账号普通重新开启**仍会回填关闭期间的用量;**被识别到的账号切换**或**撤销**之后的重新授权会隔离旧身份历史(旧账号与撤销前的用量不传;被识别到的账号切换还会换用新的设备标识),但**授权后当前桶里的新用量立即开始同步**,不必等到下一个整点。桌面事件按安装包的部署归属;独立 CLI 新事件只保留本机统计,暂不上云。同一台机器多次换账号后,网站端的设备列表可能出现多个设备条目;撤销旧设备标识不会撤销之后换账号生成的新设备标识(但每次换账号都会作废旧同意,未重新确认前本机不上传)。状态区会显示最近结果、接受桶数、等待时间与跳过原因;时间按本机时区显示(上传桶与游标本身仍是 UTC)。

**国内版与国际版的上传状态隔离**:同一台机器上的国内版与国际版分别保存本机上传状态、同意、游标、设备身份与历史回填边界,互不把另一部署的账号变化误判为本部署换号。旧共享状态只在同源证据成立并完成真实读回后归位;无法确认身份时不会擅自恢复上传或解除历史隔离。

**macOS 一键更新重启**:更新安装后由独立 helper 等当前进程退出,再经 LaunchServices 拉起应用,避免新版本已在后台运行却不回到前台。

## 常见问题

**AI 能不能读取我的文件?**

默认不能。`cat`、`head`、`grep` 等命令默认被拦截。如果你需要 AI 读取文件,把文件放到 `~/.kaya/` 下,然后告诉 AI 路径。详见 [让 AI 读取文件](#让-ai-读取文件)。

**粘贴的密钥会被发出去吗?**

命中规则的密钥会在进入对话和日志前脱敏,替换部分在 UI 上有"已脱敏"标记。识别范围包括 PEM 私钥、API Key 等常见模式,但不能保证识别所有秘密,不要把重要密钥贴进对话。图片不经过文本脱敏,也不要把含密钥的截图当成安全输入。

**API Key 安全吗?**

API Key 只保存在本机系统钥匙串,仅随请求发给你配置的模型端点 —— 不上传到 Yunhou,也不写入审计日志。**不会**发送给任何其他第三方。**不**承诺"完全不上传"——任何联网请求都需要鉴权,鉴权就需要 key,这是联网请求的基本机制。

**云端模型会收到什么?**

你选定的模型会收到对话文本、工具结果及适用的上下文;文本按各路径的保护规则处理。你主动提供的文件内容、经脱敏的终端输出也可能进入上下文;BYOK 支持的图片单独发送,不经过文本脱敏。API Key 只用于相应服务的鉴权头,不是对话正文。其他外发路径与例外见「隐私与安全边界」及隐私文档。

**怎么用本地模型?**

选择 **Ollama** 作为供应商:先在终端把 `ollama serve` 跑起来,再在 **⚙ 设置 → 模型 → + 添加供应商** 里从目录选 Ollama(端点已预填本机地址),本地端点免 API Key。也可以用「自定义」填任何本地 OpenAI 兼容端点(自托管 vLLM / LM Studio)。完全本地推理时,对话与工具输出都不离开你的电脑;若你已登录账号,使用情况心跳(仅存活时长 / 平台 / 版本)仍按设置上报,可在 **⚙ 设置 → 账户** 关闭。

**AI 误操作把我的文件删了怎么办?**

kaya 自带 AI 的 `run_shell` 不允许删除、移动或直接改写你的文件;安全重定向和经授权的配置管理有独立边界。你在终端中运行的编程 Agent 有它自己的文件权限与确认机制,kaya 的工具白名单不是对该 Agent 的全局沙箱。被拦截时 UI 会显示原因。

**为什么命令被拒绝?**

AI 试着执行的命令可能落在以下情况:

- 命令在白名单之外,默认拒绝(你可以换个问法)
- 命令是破坏性命令(如 `rm -rf`)
- 命令是交互式程序(如 `vim`、REPL)
- 命令会修改系统(如 `brew install`、`sudo`)

UI 上会显示具体的拒绝原因。

**为什么 macOS 弹文件夹访问权限?**

当 AI 试图读取你受 macOS 保护目录(桌面、下载、文稿)下的文件时,macOS 会弹出权限请求。这是 macOS 自身的隐私保护机制,所有类似工具都会触发。详见 [让 AI 读取文件](#让-ai-读取文件) 章节,推荐把文件放在 `~/.kaya/` 下避免。

**怎么让 AI 读取指定文件?**

把文件放进 `~/.kaya/`,然后在对话里告诉 AI 路径。详见 [让 AI 读取文件](#让-ai-读取文件)。

**怎么恢复断开的标签页?**

打开 **⚙ 设置** → **通用** 标签页的 **Shell** 小节,点击「立即重连」重连该会话对应的 PTY。

**为什么连接 LLM 时也报超时?**

首次连接 LLM 服务商最长 30 秒握手超时(网络不通、API Key 错误、Provider 限流都可能触发),UI 会显示"LLM 连接超时"横幅。检查网络与 API Key 后重试。

**怎么查看 AI 的历史操作?**

打开 **⚙ 设置** → **审计**,选择会话,查看事件流或运行评估。详见 [查看审计记录](#查看审计记录)。

**支持哪些平台?**

当前同时发布 macOS 与 Windows 版本:

- **macOS**:需要 macOS 12 或更高,Apple Silicon 和 Intel 通用(同一个 universal DMG)
- **Windows**:x64,提供 NSIS(`.exe`)与 MSI 两种安装包;终端为 PowerShell(pwsh 7 优先,Windows PowerShell 5.1 兜底)

**模型网关会不会拖慢速度?**

只多一跳本机回环转发(`127.0.0.1`),不上外网,延迟影响通常在毫秒级。真正的耗时来自脱敏档位:strict 只自动拦截具名 secret,基本可以忽略;balanced 增加 PII 规则,aggressive 的高熵扫描更重,对大请求会有可观开销。如果觉得慢,把网关档位调回 strict。

**为什么我的 agent 里模型名变成了 `kaya/xxx`?**

这就是网关形态:agent 配置里写的是**别名**(`kaya/<slug>`)和一个友好显示名,网关在转发时把它解析成库里的真实模型。这样做的目的是让真实供应商 / 端点 / key 不进 agent 配置。别名一旦生成就**定格不变**(改名不会改别名),旧别名永久可解析。

**agent 报 400「模型未纳入网关」怎么办?**

请求里的模型名不是可解析的 `kaya/<别名>`。常见原因:手工把 agent 配置改成了裸上游模型名、用了别的工具的默认模型、或者第三方工具第一次接入时填了裸名。改回 `kaya/<别名>`(目录页可查),或点「重新接入」。网关**不会**偷偷转发未纳管的模型,这是刻意的。若你已显式开启「全局接管 codex」且绑定的是 OpenAI ChatGPT 订阅,Codex 官方内置裸模型名是唯一的兼容例外。

**网关会存我的请求内容吗?**

不会。网关审计**零内容**(只记类别计数、字节数、实际路由);唯一的本地明细是「隐私保护统计」——它保存的是**命中片段的原文与替换后的令牌**,存在本机、默认遮罩、可筛选清空,不进 LLM 上下文、不进诊断导出,也不出本机。

**脱敏等级有什么差别?**

这里有三套**互相独立**的档位:

- **你的输入**(聊天输入框)= 恒 **aggressive**,不受设置影响,也不可降低。
- **工具输出**(五道关卡的第 5 道)= 默认 **aggressive**,可在「设置 → 通用」调整。
- **模型网关** = 独立档位,默认 **strict**:只自动拦截具名 secret,普通 PII 不自动改写;可选 balanced(具名 secret 与 PII 令牌化)/ aggressive(高熵也令牌化,误伤更多)。

聊天侧的三档语义:

- **aggressive**:识别最多种类的敏感信息,包括身份证号、手机号、邮箱、信用卡号等
- **balanced**:识别常见 API Key、AWS 凭证、Token 等
- **strict**:只识别最明显的密钥标记

推荐聊天侧保持 **aggressive**;网关侧保持默认 **strict** 可减少误拦。如果明确需要自动脱敏普通邮箱、手机号等 PII,再切 balanced 或 aggressive。

## 故障排查

**终端无响应**

1. 按 **Esc** 中断 AI 当前回合
2. 打开 **⚙ 设置** → **通用** 标签页的 **Shell** 小节,点击「立即重连」重连 PTY
3. 仍无响应,尝试 **⌘W** 关闭当前标签页,再 **⌘T** 新建

**AI 回复很慢**

- 检查网络连接
- 开启思考模式会增加延迟(推理本身需要时间)
- 在设置里切换到更快的模型

**工具调用被拒绝**

UI 会显示具体拒绝原因。常见的:

- 命令是破坏性或交互式命令:换条路径
- 命令超出白名单:换个等价工具
- 试图读取 `~/.kaya/` 之外的文件:把文件放进 `~/.kaya/`

**粘贴失效**

确认焦点在正确的输入框:终端输入框的粘贴会进入终端,对话输入框的粘贴会发给 AI。

**会话丢失**

检查 `~/.kaya/conversations/` 目录是否被清理。重启应用后,旧会话应自动从磁盘恢复。如果仍然看不到,可能需要清除应用本地状态后重新开始。

**AI 一直不响应**

流式响应静默 30 秒会自动超时,UI 上会有超时提示。可以按 **Esc** 或 **⏹** 按钮手动中断。

**macOS 弹文件夹权限**

把要读取的文件放进 `~/.kaya/` 下,不要让 AI 直接访问桌面、下载、文稿等受保护目录。

**内置模型报「上游拒绝了本次请求 (502)」**

这是上游模型服务拒绝了请求(上下文超长、内容审核或额度问题都有可能)。kaya 会先在后台自动压缩早期对话历史后重试一次(重试时消息流里会有「已自动压缩早期消息」的提示);仍然失败时,错误卡片上会给出针对具体原因的指引,并带一个**「开新会话」按钮**——上下文超长类的拒绝开新会话是最快的解法,你的终端 tab 与运行中的 agent 都不受影响。

**网关显示「被占用」或起不来**

dev 与 prod 两个构建的网关互斥:同一时间只有先启动的实例持有网关,另一个显示「被 <实例> 占用」,此时写操作会被拒绝。关掉占用方(通常是 dev 构建)再启用即可。端口被别的程序占用时网关会自动顺延到下一个可用端口,不需要手工改。

**网关开着,agent 却报 401 / 403**

先看 Agent 详情页的「接入状态」:缺凭据、OAuth 未登录 / 已过期、端点被停用都会显示「未接入 + 原因」。OAuth 供应商过期后重新登录一次;API Key 被清空时,依赖它的 agent 会退出网关形态,重新填入 key 并保存后自动接回。状态显示「已接入」仍报鉴权错时,点供应商详情页的「测试连接」区分「端点不可达」与「凭据可能无效」。

**网关开着,agent 长时间没有输出**

上游连续 120 秒(默认,可配)没有数据时,网关会主动中止并按 agent 使用的协议发一帧失败,agent 自己会重试——这不是卡死。频繁出现时先查网络与上游状态;超时与断流会写入 App 诊断日志(零内容),计数仅经 `gateway_get_status` 透出,网关页不直接展示。

**诊断日志**

遇到其他问题,打开 **⚙ 设置** → **日志与调试**,点击「打开日志目录」查看 `~/.kaya/logs/` 下的日志文件,这些日志包含 kaya 运行时的诊断信息(不含你的对话内容)。
